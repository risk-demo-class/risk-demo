# 教育行业风控系统 — 业务说明（1 页纸）

> 适用场景：职业培训 / 成人教育 / 素质教育 / 考研公考等泛教育在线平台
> 监管背景：2021「双减」后 K12 学科培训严格受限，本说明面向合规运营的成人/非学科教育场景

---

## 一、典型欺诈场景（6 大类）

### 1. 账号批量注册 & 薅羊毛
黑产利用猫池/接码平台批量创建账号，领取新人优惠券、免费试听课、邀请奖励。
- **识别特征**：同一设备/同一IP注册多个账号；注册手机号属于虚拟号段；注册后高频领取优惠但无实质学习行为。

### 2. 刷课 / 代刷学时
学生或黑产使用脚本/模拟器自动刷课程进度、挂机攒学时（常见于职业资格继续教育、学时证明类场景）。
- **识别特征**：视频播放倍速异常、单日学习时长远超合理上限、学习时段集中在凌晨、无交互行为（快进/暂停/答题）。

### 3. 恶意退费 / 「学完就退」
学生在短时间内学完课程全部内容后立刻申请全额退款，实质为免费获取课程内容。
- **识别特征**：购买到退费间隔短、退费前学习进度突增、同一用户历史退费率偏高、多账号关联退费。

### 4. 支付 & 分期欺诈
利用教育分期产品套现（虚报课程价格骗取贷款），或篡改支付参数叠加优惠。
- **识别特征**：订单金额与课程标价不符、分期申请信息与实名信息不一致、同一还款账户关联多个学生。

### 5. 虚假师资 / 虚假宣传
机构端伪造教师资质、虚构名校合作背景、承诺「包过保过」等违规宣传。
- **识别特征**：教师资质证书无法核验、宣传文案含绝对化用语、用户投诉率异常。

### 6. 内容安全违规
课程内容涉及政治敏感、低俗色情、侵权盗版（盗录其他平台课程转卖）。
- **识别特征**：课程标题/描述命中敏感词库、用户举报内容侵权、视频指纹比对命中已登记版权内容。

## 二、关键业务实体与风险字段

| 实体 | 核心字段（★表示风控关键字段） |
|------|-------------------------------|
| **用户** | ★手机号、★设备指纹（Device ID）、★注册IP、★实名认证状态、姓名(加密)、身份证号(加密)、学历、职业、注册渠道、邀请人 |
| **课程** | ★课程类别、★价格、授课教师、所属机构、课时数、上架时间、内容标签 |
| **订单** | ★订单金额、★支付方式、★优惠券/码、支付状态、订单时间、分期期数、分期机构 |
| **学习行为** | ★课程进度%、★单日学习时长、★播放倍速、★交互事件（暂停/快进/答题）、登录IP、设备信息 |
| **优惠营销** | ★优惠券领取时间、★使用条件、邀请记录、拼团记录、新人奖励领取记录 |
| **退费申请** | ★购买到退费间隔、★退费原因、★学习进度、历史退费率、退费金额 |

## 三、风控事件类型（对应 Pipeline）

借鉴电商风控的 7 步流水线模式，教育行业定义以下事件类型：

| 事件类型 | 触发时机 | 风控目标 |
|---------|---------|---------|
| `register` | 用户注册 | 检测批量注册、虚假手机号、设备关联 |
| `login` | 用户登录 | 异常登录、撞库攻击、设备/IP突变 |
| `real_name_auth` | 实名认证 | 身份伪造、冒用他人身份、未成年人冒用成年人 |
| `purchase` | 下单购买 | 支付欺诈、分期套现、批量刷单 |
| `coupon_claim` | 领取优惠券 | 营销作弊、薅羊毛、虚假邀请 |
| `course_watch` | 开始看课 / 进度更新 | 刷课、代刷学时、挂机检测 |
| `refund_apply` | 申请退费 | 恶意退费、「学完就退」 |
| `complaint` | 投诉举报 | 恶意投诉、机构端违规举报 |

每个事件进入 Pipeline 后做：特征计算（N 维）→ 规则匹配（M 条规则）→ ML 评分（可选）→ 融合决策。

## 四、决策输出（4 档）

| 决策 | 含义 | 后续动作 |
|------|------|---------|
| **通过（allow）** | 无风险，放行 | 正常业务流转 |
| **标记（mark）** | 低风险，记录观察 | 写入评估记录，不阻断 |
| **人工审核（review）** | 中高风险，需人工判 | 创建审核工单，冻结操作 |
| **拒绝（block）** | 高风险，直接阻断 | 拒绝操作，可选加入黑名单 |

## 五、国内监管合规要点

### 1. 个人信息保护法（PIPL）
- 收集学生信息遵循 **最小必要原则** — 不收集与教学/风控无关的个人信息
- **未成年人信息**：14 岁以下按敏感个人信息处理，须取得监护人单独同意
- 手机号、身份证号等存储须 **加密（AES-256 / 国密 SM4）**，日志脱敏
- 用户有权要求 **删除个人信息**（注销账户时同步删除风控存档的关联信息）

### 2. 数据安全法（DSL）
- 教育数据可能属于 **重要数据** 目录，须按等级保护要求防护
- 数据出境须通过安全评估（境外用户场景需注意）

### 3. 教育部专项监管
- **预付费资金监管**：培训收费不得超过 3 个月或 60 课时，大额订单需预警
- **内容审核**：课程内容须备案，不得含违规宣传（「保过」「包过」「速成证书」等）
- **师资公示**：教师资质须在平台显著位置公示

### 4. 网络安全法 & 等保 2.0
- **实名认证**：用户注册须绑定有效手机号（可对接运营商三要素验证）
- **日志留存**：操作日志留存不少于 **6 个月**，风控事件日志不少于 **1 年**
- **等保三级**：教育平台通常要求等保三级认证（含风控系统在内）

### 5. 未成年人网络保护条例
- 未成年人模式下限制单日使用时长、宵禁（22:00-6:00 限制）
- 不得向未成年人发送商业营销信息
- 风控规则对未成年人账号自动启用 **更高保护阈值**

## 六、架构映射（与电商风控对比）

| 维度 | 电商风控（现有） | 教育风控（目标） |
|------|-----------------|-----------------|
| 事件来源 | 下单/支付/售后 | 注册/看课/退费/认证 |
| 特征维度 | 25 维（交易+用户+商品） | ~20 维（学习行为+身份+支付+设备） |
| 规则库 | 30 条交易类规则 | 25 条（身份+行为+内容+支付混合） |
| 黑名单 | 用户/地址/电话 | 用户/设备/手机号/IP（4 类） |
| ML 模型 | XGBoost 二分类 | XGBoost 二分类（结构相同，换特征） |
| 融合策略 | 0.5×规则 + 0.5×ML | 同架构，权重可调 |
| 特殊监管 | 无 | PIPL未成年人保护 + 教部预付费监管 |
