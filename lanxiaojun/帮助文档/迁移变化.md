## 一、架构概述（未变动）

7 步 Pipeline 核心逻辑保持不动：

```
event → feature → rule → ML → score → decision → persist
```

- 评分公式：`max(hit_scores) + BONUS(3) × extra_hits`，上限 100
- 双轨融合：`0.5 × rule_score + 0.5 × ML_score`
- 否决机制：任何"极高"规则命中 → 强制拒绝，ML 不可覆盖
- 条件建案：仅"人工审核"或"拒绝"才写入 risk_case

## 五、6 级黑名单优先级

| 优先级 | 类型 | 说明 |
|--------|------|------|
| 1 (最高) | 用户 | 直接封用户 |
| 2 | 学号 | 通过 student_profile.student_id 查 |
| 3 | 身份证 | 通过 student_profile.id_card_hash 查 |
| 4 | 设备指纹 | 通过 request.device_id 查 |
| 5 | 支付账号 | 仅 purchase 事件查 |
| 6 (最低) | 手机号 | 通过 UserInfo.phone 查 |

命中任意一级 → 立即返回 final_score=100, decision="拒绝"，不走引擎。
