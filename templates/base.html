物流风控系统 · 使用指引
① 仪表盘 / Dashboard

做什么：给管理人员看的"全局总览"，一眼掌握今天/本周/本月风控整体情况。

主要内容：

  • 今日评估数、案件数、黑名单总数、AI 命中率（4 张核心卡片）
  • 近 7/30 天风险评估走势折线图 + 风险等级分布饼图
  • Top 高危用户、最近创建/修改的规则、最近新加入的黑名单
→ 打开仪表盘
② 风险检查（最常用）

做什么：给任意"业务事件"跑一次完整的风控决策，立刻返回「通过/标记/人工审核/拒绝」。

何时用：客服接到用户投诉、运营要审核一个可疑运单、需要复核任意一笔交易。

4 种事件类型（物流版）：

  • 寄件下单：用户在小程序/APP 刚下单（最常用）
  • 到付签收：收件人拒收到付件、或者签收后投诉（拒收率画像用到）
  • 跨境申报：国际快件向海关申报（危险品、瞒报校验的核心入口）
  • 投诉申诉：用户主动发起投诉或申诉（投诉滥用检测）

业务 ID（Source ID）填什么：跟事件类型对应——

  • 寄件下单 → 运单号 SHIPxxxxxx
  • 到付签收 → 运单号 SHIPxxxxxx
  • 跨境申报 → 报关单号 DECLxxxxxx
  • 投诉申诉 → 投诉单号 TICKET-1 / 数字 ID
→ 打开风险检查
③ 评估历史

做什么：回溯所有风控检查的结果（包括已经通过/标记/案件已结案的）。相当于"全量审计日志"。

和案件管理的区别：案件只显示待办（待审核+审核中）；评估历史是全量，包括"直接通过"和"标记后自动通过"的。

筛选维度：决策 / 风险等级 / 事件类型 / 用户 ID，都可以组合。默认每页 20 条。

→ 打开评估历史
④ 规则管理

做什么：配置规则引擎（风控的"左脑"，占最终评分 60% 权重）。所有命中规则会加权融合，得到规则总分。

字段说明（新建/编辑规则时会用到）：

字段说明示例
规则 ID唯一标识，建议 L001 / L002 递增L015
分类 (8 类)见「业务概念」Tab危险品瞒报
风险等级低 / 中 / 高 / 极高（仅标签展示，真实扣分看 risk_score）高
分值 0-100最重要！这条规则命中时贡献多少分（和其他规则加权后触发 VETO 一票否决）60
动作通过 / 标记 / 人工审核 / 拒绝人工审核
优先级数字越大越先执行（也决定列表排序），0 为默认90
条件表达式 (JSON)匹配字段的逻辑条件（25 维特征名）{"field":"sender_recent_refund_rate","op":">=","value":0.3}
→ 打开规则管理
⑤ 黑名单管理

做什么：把确认欺诈/高危的对象加进 6 类黑名单，匹配到会直接短路出"拒绝"（不再跑后面的规则和 ML）。

6 类黑名单（物流版，依次命中优先级从高到低）：

  1. 用户：user_id（最严，命中直接拒）
  2. 身份证号：SHA256 或明文（实名风险共用）
  3. 手机号：138xxxxxxx 格式
  4. 地址：address_id 或 地址文本（频繁退货高发地址）
  5. 运单号：特定已被标记的运单（走异常流程）
  6. 设备指纹：dev-xxx（模拟器 / 多账号共用设备）

⚠️ 使用原则：只有人工核实确定是恶意时才加；如果是"疑似"请走「人工审核」案件流程，别滥用黑名单（会影响正常用户收寄件）。

→ 打开黑名单
⑥ 案件管理（审核台）

做什么：风控双轨判定为「人工审核」的全部事项。给运营人员的工作台，通过 / 拒绝 / 关闭 三选一。

审核流程：

  1. 点「详情」查看命中了哪几条规则、ML 评分多少、用户历史画像（总运单数 / 拒收率 / 投诉次数）
  2. 如果用户历史画像非常糟糕（拒收率 >30%、投诉 5+ 次）→ 勾选「拒绝时加入黑名单」一次性处理
  3. 填审核人（默认 admin）和审核意见 → 点 绿色通过 / 红色拒绝 / 灰色关闭
→ 打开案件
⑦ AI 助手

做什么：用自然语言代替手动点页面。背后是 LangChain Agent + 业务工具集（SQL、查规则、查黑名单、查案件、算风险）。

典型问法示例：

  • "帮我查一下用户 RISK001 的所有运单和风险画像"
  • "最近 7 天有哪些规则被修改了？"
  • "对跨境申报 DECL007 执行一次风控检查"
→ 打开 AI 助手
📌 双轨风控架构（为什么有两套结果）

最终分 = 0.6 × 规则分 + 0.4 × ML 分。

  • 规则引擎（60%）：运营写的 30 条 Lxxx 规则，可解释、可调整
  • ML 模型（40%）：XGBoost 训练的 25 维分类器，学习历史标签的隐性模式
  • VETO 一票否决（阈值 90 分）：规则分 ≥90 → 直接「拒绝」，不再融合 ML
📌 规则的 8 大分类（物流版）
① 寄件欺诈：虚报寄件人信息、批量虚假下单
② 实名风险：身份证号 SHA256 匹配、实名失败
③ 危险品瞒报：报关品名与实际不符 / 含违禁词
④ 跨境异常：高风险目的地、申报价值不符
⑤ 到付拒收：近期拒收率、签收异常
⑥ 地址风险：历史高发退货/投诉地址
⑦ 投诉滥用：同一用户短时间内多次投诉
⑧ 综合风险：跨多类别的通用兜底
📌 4 种决策（全页面统一）
决策含义触发阈值参考
通过正常放行，不进入人工最终分 < 40
标记观察项，记录评估不进案件40 ≤ 分 < 60
人工审核自动创建案件 → 进入 案件管理60 ≤ 分 < 90
拒绝自动拦截（黑名单命中 / VETO 90+）分 ≥ 90
📌 25 维特征（规则条件 JSON 的 field 填这些）

这些字段是规则条件 {"field": "...", "op": ">=", "value": x} 里 field 的合法取值，写错了会触发"条件不匹配"，规则永不命中。

① 用户画像（6 项）
  • user_risk_score 画像评分
  • total_shipments 总运单数
  • sender_recent_refund_rate 近期拒收率
  • sender_total_refunds 总拒收次数
  • complaint_count 投诉次数
  • assessment_count 历史评估数
② 运单本身（6 项）
  • order_total_amount 申报价值
  • waybill_weight_kg 重量(kg)
  • item_count 件数
  • cod_amount 到付金额
  • is_cross_border 跨境(0/1)
  • is_cod 到付(0/1)
③ 实名与设备（6 项）
  • real_name_verified 实名通过
  • id_card_risk 身份证风险分
  • phone_risk 手机号风险分
  • device_risk 设备指纹风险分
  • device_shared_users 设备共用人数
  • new_account_days 新号天数
④ 地址与地理（4 项）
  • address_risk 地址风险分
  • address_shipment_count 该地址总运单数
  • same_address_users 同地址人数
  • high_risk_region 是否高风险地区
⑤ 跨境/危险品（3 项）
  • declaration_value_mismatch 申报价值异常(0/1)
  • dangerous_goods_keywords 命中违禁词数
  • sanctioned_country 制裁国(0/1)

contains (字符串包含)

第一次上手建议操作顺序
  1. 先到「规则管理」把 L001~L030 30 条初始化规则读一遍（建立业务直觉）
  2. 到「风险检查」拿几个示例用户 RISK001 / RISK002 / NORMAL001 跑一遍检查
  3. 如果评估分 ≥ 60，去「案件管理」走一遍审核流程
  4. 确认是恶意用户，最后再加到「黑名单」里
