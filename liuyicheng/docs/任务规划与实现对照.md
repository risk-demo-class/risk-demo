# 第六章任务规划与实现对照

| 阶段 | 先做什么 | 编程逻辑 | 产物/验收 |
|---|---|---|---|
| 1. 行业调研 | 固定四类事件和欺诈链路 | 建立 `event_type → 业务模型 → 时间字段` 路由 | `1-业务说明.md` |
| 2. 数据层 | 替换旧电商 ORM 和 DDL | 8 张业务表存事实，9 张核心表存风控结果；敏感标识哈希化 | `models_business.py`、4 个初始化 SQL、187+ 样例行 |
| 3. 特征层 | 先定义稳定特征契约 | 用户/事件/上下文三组共 25 维，训练与推理使用同一顺序 | `feature.py`、`FEATURE_COLUMNS` |
| 4. 规则层 | 把业务描述翻译成 JSON 条件树 | 叶子条件做比较，`and/or` 递归组合，通用规则覆盖四类事件 | 12 条规则，包含任务书 8 条样例规则 |
| 5. 决策层 | 复用原七步决策链 | 规则分与 ML 概率校准后取更严格决策；拒绝规则具有否决权 | 评估、案件、画像和可解释命中详情 |
| 6. 接口层 | 收敛为统一四字段请求 | 校验 `source_id` 存在、归属用户、交易类型与事件类型一致 | `/api/risk/check` 四场景可调用 |
| 7. 模型层 | 用同一 25 维生成训练矩阵 | 0=通过/标记，1=人工审核/拒绝；分层拆分、早停、AUC/F1 | `xgb_model.json`、`model_metrics.json` |
| 8. Agent/页面 | 工具调用 service 而非复制 SQL 逻辑 | 8 个工具覆盖检查、案件、画像、名单、统计、趋势、规则和业务查询 | Web 页面 + Agent |
| 9. 工程化 | 再做初始化、容器和测试 | 默认不删库；显式 `--reset`；容器单 worker 避免重复调度 | README、Docker、pytest |

## 关键依赖顺序

```text
业务表/样例数据
  → 事件校验与适配
  → 25 维特征
  → 12 条规则
  → 七步决策与九张风控表
  → 训练数据和 XGBoost
  → API / 页面 / Agent / 告警
```

相邻阶段不能反过来做：规则必须引用已经稳定的特征名；模型必须使用在线推理同一列顺序；页面与 Agent 必须调用已经稳定的 API/service 契约。
