# 旅游 OTA 风控项目结构说明

本文档描述当前 `AI_Risk` 旅游风控项目的真实代码与数据库结构，包括项目分层、16 张数据表、25 维风控特征、8 条旅游规则和完整运行链路。

## 1. 系统定位

当前项目已经从电商风控场景改造成旅游 OTA 风控场景，覆盖以下五类业务事件：

1. 机票预订
2. 酒店预订
3. 签证申请
4. 跟团游报名
5. 退改申请

系统采用“规则引擎 + XGBoost 模型”双轨决策：

```text
旅游业务事件
    ↓
业务实体校验与黑名单检查
    ↓
生成风险事件 risk_event
    ↓
计算 25 维 risk_feature
    ↓
8 条旅游规则匹配 + XGBoost 推理
    ↓
风险评分与最终决策
    ↓
risk_assessment
    ↓
risk_case / risk_user_profile / risk_alert
```

```text

```

## 5. 九张风控核心表

### 5.1 `risk_rule`：风控规则配置表

保存规则 ID、名称、分类、JSON 条件、风险等级、分数、动作、优先级、启停状态和软删除时间。

### 5.2 `risk_event`：风控事件审计表

每次进入七步决策链路都会产生一条事件记录，保存事件类型、业务来源 ID、用户 ID 和事件快照。

### 5.3 `risk_feature`：风控特征快照表

每次风险评估保存 25 行特征快照：

```text
一条 risk_event → 25 条 risk_feature
```

核心字段包括 `event_id`、`entity_type`、`entity_id`、`feature_name`、`feature_value` 和计算时间。

### 5.4 `risk_assessment`：风控评估结果表

保存：

- 命中的规则 JSON
- 命中规则数量
- 最终分数
- 风险等级
- 最终决策
- XGBoost 风险概率
- XGBoost 单独决策

### 5.5 `risk_case`：风控案件表

当最终决策为人工审核或拒绝时创建案件。人工审核进入待审核状态，自动拒绝案件直接进入已拒绝状态。

### 5.6 `risk_blacklist`：核心风控黑名单表

用于保存核心用户、手机号等通用黑名单。旅游证件和设备类黑名单由 `blacklist_extra` 补充。

### 5.7 `risk_user_profile`：用户风险画像表

保存用户累计风险分、风险等级、订单统计、评估次数和最近评估时间。

### 5.8 `risk_action_log`：风控操作审计日志表

记录规则创建和修改、案件审核、自动拒绝、黑名单操作等管理动作。

### 5.9 `risk_alert`：风控告警记录表

记录待审案件积压、规则命中率突降、拒绝率过高等系统运行告警。

## 6. 二十五维旅游风控特征

为了兼容原有 XGBoost 模型，特征键名保持不变，但实际业务含义已改为旅游场景。

```text
14 个用户特征 + 8 个订单特征 + 3 个目的地特征 = 25 维
```

### 6.1 用户维度：14 个

| 特征名 | 旅游业务含义 | 数据来源 |
|---|---|---|
| `user_total_orders` | 历史旅游订单总数 | `order_info` |
| `user_orders_30d` | 最近 30 天订单数 | `order_info.book_time` |
| `user_orders_7d` | 最近 7 天订单数 | `order_info.book_time` |
| `user_total_amount` | 历史旅游消费总额 | `order_info.total_amount` |
| `user_avg_order_amount` | 历史平均订单金额 | `order_info` |
| `user_max_order_amount` | 历史最大单笔订单金额 | `order_info` |
| `user_refund_count` | 历史退改申请次数 | `risk_event` |
| `user_postsale_count` | 近 90 天累计拒签次数 | `visa_application.reject_history` |
| `user_refund_rate` | 退改次数除以历史订单数 | `risk_event`、`order_info` |
| `user_postsale_rate` | 近 90 天拒签次数除以历史订单数 | `visa_application`、`order_info` |
| `user_refund_amount` | 实名状态编码：未实名 0、已实名 1、已认证 2 | `user_info.real_name_status` |
| `user_cancel_count` | 近 30 天签证申请的不同目的国数 | `visa_application.dest_country` |
| `user_complaint_count` | 用户乘客证件命中有效黑名单的数量 | `passenger_info`、`blacklist_extra` |
| `user_address_count` | 历史不同乘客证件数量 | `passenger_info` |

### 6.2 订单维度：8 个

| 特征名 | 旅游业务含义 | 数据来源 |
|---|---|---|
| `order_total_amount` | 当前订单总金额 | `order_info.total_amount` |
| `order_item_count` | 当前订单乘客或入住人数 | `order_info.passenger_count` |
| `order_sku_count` | 一小时内同一用户预订同航班的累计票数 | `booking_flight`、`order_info` |
| `order_discount_amount` | 下单用户账户注册天数 | `user_info.account_age_days` |
| `order_discount_rate` | 本单乘客证件与历史乘客证件的匹配率 | `passenger_info` |
| `order_pay_interval_sec` | 提前预订天数 | `book_time`、`depart_date` |
| `order_is_night` | 是否在凌晨 1 点至 5 点下单 | `order_info.book_time` |
| `order_category_count` | 行程或酒店入住天数 | `order_info`、`booking_hotel` |

### 6.3 目的地维度：3 个

`addr_` 前缀为兼容旧模型而保留，实际含义已经从地址变为旅游目的地。

| 特征名 | 旅游业务含义 | 数据来源 |
|---|---|---|
| `addr_total_count` | 用户历史有目的地的订单数 | `order_info` |
| `addr_province_count` | 用户历史不同目的国家或地区数量 | `order_info.dest_country` |
| `addr_is_new` | 当前目的地是否首次出现 | `order_info.dest_country` |

## 7. 当前启用的八条旅游规则

### 7.1 R030：黑护照拦截

```json
{"field": "user_complaint_count", "op": ">=", "value": 1}
```

- 含义：乘客护照命中有效业务黑名单。
- 风险等级：极高。
- 风险分：100。
- 动作：拒绝。
- 优先级：110。

### 7.2 R001：拒签历史拦截

```json
{"field": "user_postsale_count", "op": ">=", "value": 2}
```

- 含义：近 90 天累计拒签历史不少于 2 次。
- 风险等级：极高。
- 风险分：95。
- 动作：拒绝。
- 优先级：100。

### 7.3 R008：黄牛囤票

```json
{"field": "order_sku_count", "op": ">=", "value": 5}
```

- 含义：同一用户一小时内预订同一航班累计不少于 5 张票。
- 风险等级：极高。
- 风险分：95。
- 动作：拒绝。
- 优先级：95。

### 7.4 R002：短期多国签证

```json
{"field": "user_cancel_count", "op": ">=", "value": 3}
```

- 含义：用户近 30 天签证申请涉及至少 3 个不同目的国。
- 风险等级：高。
- 风险分：75。
- 动作：人工审核。
- 优先级：90。

### 7.5 R005：大额跨境游

```json
{"field": "order_total_amount", "op": ">", "value": 50000}
```

- 含义：单笔旅游订单金额超过 50000 元。
- 风险等级：高。
- 风险分：70。
- 动作：人工审核。
- 优先级：80。

### 7.6 R025：新用户大单

```json
{
  "and": [
    {"field": "order_discount_amount", "op": "<", "value": 7},
    {"field": "order_total_amount", "op": ">", "value": 10000}
  ]
}
```

- 含义：注册不足 7 天的新用户提交金额超过 10000 元的订单。
- 风险等级：中。
- 风险分：50。
- 动作：标记。
- 优先级：60。

### 7.7 R012：凌晨突击下单

```json
{
  "and": [
    {"field": "order_is_night", "op": "==", "value": 1},
    {"field": "order_pay_interval_sec", "op": "<", "value": 7}
  ]
}
```

- 含义：凌晨 1 点至 5 点下单，且距离出发不足 7 天。
- 风险等级：中。
- 风险分：45。
- 动作：标记。
- 优先级：50。

### 7.8 R018：乘客信息不一致

```json
{
  "and": [
    {"field": "user_address_count", "op": ">=", "value": 1},
    {"field": "order_item_count", "op": ">", "value": 0},
    {"field": "order_discount_rate", "op": "<", "value": 0.3}
  ]
}
```

- 含义：用户有历史乘客，本单存在乘客，且乘客证件历史匹配率低于 30%。
- 风险等级：中。
- 风险分：40。
- 动作：标记。
- 优先级：45。

## 8. 规则和特征对应关系

| 规则 | 使用的特征 |
|---|---|
| R030 黑护照拦截 | `user_complaint_count` |
| R001 拒签历史拦截 | `user_postsale_count` |
| R008 黄牛囤票 | `order_sku_count` |
| R002 短期多国签证 | `user_cancel_count` |
| R005 大额跨境游 | `order_total_amount` |
| R025 新用户大单 | `order_discount_amount`、`order_total_amount` |
| R012 凌晨突击下单 | `order_is_night`、`order_pay_interval_sec` |
| R018 乘客信息不一致 | `user_address_count`、`order_item_count`、`order_discount_rate` |

## 9. 风险等级和动作

| 风险等级 | 典型动作 |
|---|---|
| 低 | 通过 |
| 中 | 标记 |
| 高 | 人工审核 |
| 极高 | 拒绝，一票否决 |

命中多条规则时，规则评分采用：

```text
规则分 = 最高命中规则分 + 多规则命中奖励
```

如果任意一条命中规则的等级为“极高”，系统触发一票否决，最终结果强制拒绝，不会被 XGBoost 低分推翻。

## 10. XGBoost 双轨决策

XGBoost 使用固定顺序的 25 维特征进行二分类：

```text
标签 0：通过、标记
标签 1：人工审核、拒绝
```

模型输出拒绝概率，再转换为 ML 风险分，与规则分按配置权重融合。模型没有加载时，系统自动降级为纯规则模式，不影响核心业务运行。

## 11. 七步决策流水线

`app/engine/decision.py` 中的主流程：

1. 构建风险检查上下文。
2. 创建 `risk_event` 事件记录。
3. 计算 25 维旅游特征。
4. 保存 25 条 `risk_feature` 特征快照。
5. 加载并匹配启用规则。
6. 计算规则分、XGBoost 分和最终决策。
7. 保存 `risk_assessment`，按需创建案件并更新用户画像。
