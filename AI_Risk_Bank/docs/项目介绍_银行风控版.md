# AI_Risk 银行风控系统项目介绍

## 1. 项目概述

本项目是在尚硅谷 `AI_Risk` 电商风控系统基础上完成的银行业务化改造版本，面向信用卡申请、贷款申请、大额转账和异常登录四类核心银行场景。

系统保留原项目的通用风控能力：

```text
事件驱动
+ 风控核心 9 张表
+ 25 维行为特征
+ 可配置业务规则
+ XGBoost 机器学习
+ 规则/模型双轨融合
+ 案件、画像、审计、告警闭环
```

本版本的目标不是开发完整银行核心系统，而是构建一个可以演示“银行风险识别—决策—审计—人工审核”全过程的风控平台原型。

## 2. 银行业务痛点

银行业务风险通常不是一个字段异常，而是多个行为信号组合异常：

- 客户在陌生城市、陌生设备上突然发起大额转账。
- 凌晨短时间内连续操作多个账户或银行卡。
- 同一设备被多个客户使用，形成疑似团伙关联。
- 贷款申请金额与收入、负债情况不匹配。
- 登录 IP 属于代理网络、Tor 出口或高风险地址。
- 收款银行卡、设备、IP 或身份证进入黑名单。

系统用规则保证确定性风险底线，用 XGBoost 学习复杂组合风险，再通过人工案件完成最终处置。

## 3. 业务范围和事件

| 事件 | 业务 ID | 风控目标 |
|---|---|---|
| 信用卡申请 | 客户 ID | KYC、信用分、申请额度和客户历史行为 |
| 贷款申请 | `loan_id` | 多头借贷、负债率、收入和申请金额 |
| 大额转账 | `txn_id` | 异地、凌晨、新设备、多卡归集、黑卡 |
| 异常登录 | `login_id` | 新设备、多人共用设备、代理 IP/Tor、失败爆发 |

统一 API 请求仍使用：

```json
{
  "event_type": "大额转账",
  "source_id": "TX1002",
  "user_id": "U1002",
  "event_data": {"channel": "手机银行"}
}
```

## 4. 系统核心数据表

### 4.1 银行业务表

| 表 | 用途 |
|---|---|
| `bank_user_info` | 客户身份、KYC、信用分、账户状态和常用城市 |
| `bank_card` | 客户与银行卡关联、卡类型和额度 |
| `bank_transaction` | 转账/支付流水、金额、渠道、设备和 IP |
| `loan_application` | 贷款金额、期限、收入、用途和负债率 |
| `login_log` | 登录时间、成功失败、设备、IP 和地理位置 |
| `device_fingerprint` | 设备指纹与客户的关联关系 |
| `ip_geo_location` | IP 城市、运营商、代理和 Tor 属性 |
| `bank_blacklist_extra` | 银行专属设备/IP/银行卡/身份证黑名单 |

### 4.2 风控核心 9 张表

```text
risk_rule          规则配置
risk_event         事件审计
risk_feature       特征快照
risk_assessment    评估结果
risk_case          人工审核案件
risk_blacklist     公共黑名单
risk_user_profile  客户风险画像
risk_action_log    操作审计
risk_alert         运营告警
```

业务表描述银行对象，风控表描述风控过程和风控结果，两者解耦，便于将同一套风控引擎迁移到其他行业。

## 5. 风控处理流程

```text
1. 客户调用风险检查 API
2. 校验客户和业务 ID 的归属关系
3. 检查公共黑名单和银行扩展黑名单
4. 命中黑名单则直接拒绝并短路
5. 创建 risk_event 事件审计记录
6. 从客户、交易、贷款、登录、设备、IP 表计算 25 维特征
7. 将每个特征写入 risk_feature 快照表
8. 按 event_type 加载银行规则
9. 规则引擎匹配条件并计算 rule_score
10. XGBoost 输出拒绝概率和 ML 决策
11. 将规则风险分与 ML 风险分进行双轨融合
12. 极高风险规则执行 veto，最终强制拒绝
13. 保存 risk_assessment
14. 人工审核场景创建 risk_case
15. 更新 risk_user_profile，并产生审计/告警记录
16. 返回风险等级、最终决策、命中规则和 ML 结果
```

## 7. 业务规则

当前银行版至少包含以下规则：

| 规则 | 条件 | 等级 | 决策 |
|---|---|---|---|
| 异地大额转账 | 异地信号 + 金额 ≥ 50000 | 极高 | 拒绝 |
| 凌晨密集操作 | 凌晨时段 + 1 小时内多笔交易 | 高 | 人工审核 |
| 新设备大额交易 | 新设备 + 金额 ≥ 30000 | 高 | 人工审核 |
| 多卡归集 | 短时间多卡资金归集 | 极高 | 拒绝 |
| 信贷申请突击 | 短期高频贷款申请 | 高 | 人工审核 |
| 设备多人共用 | 同设备关联多个客户 | 中 | 标记 |
| 代理 IP/Tor | IP 命中代理/Tor 风险环境 | 中 | 标记 |
| 黑卡拦截 | 收款卡命中黑名单 | 极高 | 拒绝 |
| 高负债贷款申请 | 历史异常比例高且申请贷款 | 高 | 人工审核 |
| KYC 不足高额度申请 | KYC/客户行为不足但申请额度高 | 高 | 人工审核 |

规则结果具备可解释性、可配置性和可审计性；运营人员可以通过 `risk_rule` 管理规则状态、优先级、风险等级和触发动作。

## 8. XGBoost 与双轨融合

规则轨负责强业务约束，模型轨负责捕获复杂组合模式。

```text
rule_score = 最高命中规则分 + 多规则加分
ml_score   = 100 × (1 - exp(-3 × P(拒绝)))
final_score = 0.5 × rule_score + 0.5 × ml_score
```

模型未加载时自动降级到纯规则模式，保证风控服务仍然可用。

若命中“极高”规则，融合完成后重新执行 veto：

```text
decision = 拒绝
risk_level = 极高
final_score >= 90
```

因此，XGBoost 可以增强规则，但不能推翻银行业务底线。

## 9. 典型演示场景

### 场景一：正常客户转账

`U1001` 使用历史设备和常用城市发起小额转账，规则不命中，模型风险低，最终通过。

### 场景二：新设备大额转账

`U1003` 使用新设备发起 35000 元交易，命中新设备大额规则，进入人工审核或拒绝。

### 场景三：异地/凌晨大额转账

`U1002` 在凌晨使用异地环境发起 60000 元交易，命中高风险规则；若命中极高规则，veto 强制拒绝。

### 场景四：黑设备和 Tor 登录

`U1004` 使用被标记的设备和 Tor 出口登录，银行扩展黑名单优先拦截，不再进入普通模型流程。

## 10. 与原电商项目的区别

| 对比项 | 原电商版 | 银行版 |
|---|---|---|
| 核心对象 | 用户、订单、商品、收货地址、售后 | 客户、银行卡、交易、贷款、登录、设备、IP |
| 事件 | 下单、支付、售后申请、物流投诉 | 信用卡申请、贷款申请、大额转账、异常登录 |
| 用户行为 | 订单频次、退款率、消费金额 | 交易频次、冲正率、投诉率、设备使用历史 |
| 当前业务 | 订单金额、商品数、折扣、支付间隔 | 交易金额、资金节点、贷款金额、渠道和设备 |
| 地址特征 | 收货地址数量、省份数、新地址 | 登录/交易设备数量、省份数、新设备 |
| 黑名单 | 用户、地址、手机号 | 公共用户 + 设备、IP、银行卡、身份证 |
| 规则重点 | 订单欺诈、退款滥用、地址风险、物流投诉 | 异地、大额、凌晨、新设备、多卡归集、多头借贷 |
| 人工案件 | 异常订单和售后审核 | 交易欺诈、信贷风险和账户接管调查 |
| 数据敏感性 | 商品和订单数据 | 身份、银行卡、设备和 IP，必须脱敏 |
| 风控底线 | 极端订单、极高退款率等 | 黑卡、异地大额、团伙设备、账户接管等 |

未改变的部分：风控核心 9 张表、25 维输入契约、事件审计、特征快照、规则匹配、XGBoost、双轨融合、veto、案件和画像闭环。

## 11. 项目价值

- 验证通用风控引擎与行业业务层解耦。
- 体现银行交易风控、账户安全和信贷风险的组合识别思路。
- 同时具备规则可解释性与机器学习泛化能力。
- 保留完整的风险回溯、人工审核、审计和告警能力。
- 为后续接入真实征信、设备画像、IP 风险库提供演示原型基础。
