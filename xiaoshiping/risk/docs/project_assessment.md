# 项目运行与真实性评估

## 已跑通的流程

1. `scripts/init_db.py` 重建 `manufacturing_risk` 并写入制造业主数据、业务单据、规则和风险事件。
2. `scripts/gen_training_data.py` 从 MySQL 关联业务表生成 16 特征训练 CSV。
3. `scripts/train_xgb_model.py` 使用 80/20 分层切分训练 XGBoost 并输出 `val_auc`、`val_f1`。
4. `app.py` 提供驾驶舱、事件处置、工单模型评估、规则和模型监控页面。
5. 风险事件状态更新会写回 `risk_event.handled_status`。

已验证：五个页面返回 HTTP 200，MySQL 连接正常，模型能加载，工单评分 API 能返回结果，风险事件状态更新可写回并恢复。

## 真实性结论

| 维度 | 结论 |
|---|---|
| 业务域 | 真实：供应商、来料、IQC、BOM、工单、设备、质量、发运、客诉和 LOTO 均是常见离散制造场景。 |
| 风险规则 | 真实：资质过期、未检领料、参数越限、维护逾期、未放行发运等规则可用于真实工厂。 |
| 演示数据 | 模拟：当前数据由 SQL 批量构造，不来自 ERP/MES/WMS/QMS/EAM。 |
| 训练标签 | 模拟：当前高风险标签由典型模式注入，而非真实处置结果。 |
| 模型指标 | 教学级：`val_auc=1.0000`、`val_f1=1.0000` 仅说明合成数据可分性强，不可代表上线效果。 |

## 上线前优先改造

1. 接入真实系统数据和真实人工处置标签。
2. 实现实时规则引擎和案件/审批闭环。
3. 加入用户认证、权限、审计、脱敏、SLA 与告警。
4. 建立模型版本、特征版本、数据漂移和效果监控。
5. 使用时间切分、PR-AUC、召回率、误报率和业务损失验证模型。
6. 补齐批次追溯、工艺路线、控制计划、CAPA/8D、OEE 与 IoT 时序数据。
