# 教育风控后端与前端

## 启动

```bash
docker compose up -d
.venv/bin/python run_app.py
```

访问地址：

- 管理台：<http://127.0.0.1:8000>
- OpenAPI：<http://127.0.0.1:8000/docs>
- 健康检查：<http://127.0.0.1:8000/api/health>

如果已经激活 `.venv`，第二条命令可以写成 `python run_app.py`。

## 页面

- 风险态势：评估量、风险率、案件数、账号规模和最新评估。
- 风险检查：选择教育事件并运行 25 维特征与 8 条规则。
- 规则中心：查看和编辑 JSON 条件、等级、分值、决策、优先级，并启停规则；版本号防止并发覆盖。
- 评估历史：筛选和查看事件、规则、特征快照。
- 人工案件：查看待审核案件并提交通过、拒绝或关闭结论。
- 黑名单：管理用户 ID、学号、身份证、设备指纹和直播账号。
- 学员画像：查看账号、设备、订单、退费和最近评估信息。

## 后端结构

- `app/main.py`：FastAPI 入口。
- `app/routers/`：按 dashboard、risk、rule、assessment、case、blacklist、profile 和 pages 拆分的 HTTP 路由。
- `app/api.py`、`app/pages.py`：为已有导入保留的兼容入口，新代码不再往这里堆接口。
- `app/service/risk.py`：风险检查事务闭环。
- `app/service/errors.py`：与 FastAPI 解耦的领域异常。
- `app/engine/feature.py`：25 维教育特征。
- `app/engine/rule.py`：数据库驱动的 JSON 条件校验与通用求值器。
- `app/engine/decision.py`：无 HTTP、无事务的纯决策计算。
- `templates/` 与 `static/`：管理台页面、样式和交互。

路由层只处理 HTTP 参数、依赖注入和状态码；特征、规则和事务逻辑分别放在 `engine` 与 `service`，不要把复杂 SQL 或决策流程重新写回路由文件。

规则的 `rule_condition`、`risk_score` 和 `action` 是运行时唯一事实来源；Python 不再保存另一份阈值。风险检查写入出现异常时会统一回滚事务。

## 当前边界

这是可运行的单体 MVP，适合课程项目和本地演示。当前未实现登录鉴权、权限分级、生产密钥管理、异步任务队列和外部学历源真实对接；生产部署前必须补齐这些能力。
