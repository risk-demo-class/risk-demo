# 教育风控字段设计

> 数据库：MySQL 8.0，数据库名：`risk_proj`。本文只记录用户已经确认的字段方案；未确认的表不提前固化。

## 通用约定

- 物理表名和字段名统一使用 `snake_case`。
- 存储引擎使用 InnoDB，字符集使用 `utf8mb4`。
- 时间字段保留毫秒精度，使用 `DATETIME(3)`。
- 外键列必须建立索引；业务窗口查询根据主体、状态和事件时间建立联合索引。
- 核心业务数据原则上不物理删除；用户主数据被引用时采用 `RESTRICT`。

## 1. `user_info` — 用户信息表

| 字段 | 类型 | 可空 | 默认值 | 键/索引 | 说明 |
|---|---|---:|---|---|---|
| `user_id` | `VARCHAR(50)` | 否 | 无 | PK | 平台用户业务 ID |
| `name` | `VARCHAR(100)` | 否 | 无 |  | 用户姓名 |
| `role` | `VARCHAR(20)` | 否 | 无 | `idx_user_role` | 学生、家长或老师 |
| `student_id` | `VARCHAR(50)` | 是 | `NULL` | UNIQUE | 学号，仅学生需要；MySQL 唯一索引允许多个 NULL |
| `real_name_status` | `VARCHAR(20)` | 否 | `未认证` |  | 未认证、认证中、已认证或认证失败 |
| `register_at` | `DATETIME(3)` | 否 | 无 | `idx_user_register_at` | 用户注册时间 |
| `created_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` |  | 记录创建时间 |
| `updated_at` | `DATETIME(3)` | 否 | 当前时间并自动更新 |  | 记录更新时间 |

约束：

- `chk_user_role`：`role IN ('学生', '家长', '老师')`。
- `chk_real_name_status`：`real_name_status IN ('未认证', '认证中', '已认证', '认证失败')`。
- `uk_user_student_id (student_id)`。

## 2. `user_device` — 用户设备关联表

| 字段 | 类型 | 可空 | 默认值 | 键/索引 | 说明 |
|---|---|---:|---|---|---|
| `relation_id` | `BIGINT UNSIGNED` | 否 | 自增 | PK | 设备关联记录 ID |
| `user_id` | `VARCHAR(50)` | 否 | 无 | FK | 关联用户 |
| `device_fingerprint` | `CHAR(64)` | 否 | 无 | 联合索引 | 规范化后生成的设备指纹摘要，不保存原始设备数据 |
| `first_seen_at` | `DATETIME(3)` | 否 | 无 |  | 首次关联时间 |
| `last_seen_at` | `DATETIME(3)` | 否 | 无 | 联合索引 | 最近活跃时间；R008 使用最近 180 天记录 |
| `created_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` |  | 记录创建时间 |

索引与外键：

- `uk_user_device (user_id, device_fingerprint)`：同一关联只保存一条，重复上报更新 `last_seen_at`。
- `idx_device_active (device_fingerprint, last_seen_at, user_id)`：计算同设备活跃学员数。
- `idx_user_device_active (user_id, last_seen_at)`：查询用户近期设备。
- `fk_user_device_user (user_id) REFERENCES user_info(user_id) ON DELETE RESTRICT ON UPDATE CASCADE`。

## 3. `course` — 课程信息表

| 字段 | 类型 | 可空 | 默认值 | 键/索引 | 说明 |
|---|---|---:|---|---|---|
| `course_id` | `VARCHAR(50)` | 否 | 无 | PK | 课程业务 ID |
| `name` | `VARCHAR(150)` | 否 | 无 |  | 课程名称 |
| `category` | `VARCHAR(50)` | 否 | 无 | 联合索引 | 课程分类 |
| `price` | `DECIMAL(12,2)` | 否 | 无 | CHECK | 课程当前标价 |
| `teacher_id` | `VARCHAR(50)` | 否 | 无 | FK | 授课老师用户 ID；应用层校验角色为老师 |
| `total_hours` | `DECIMAL(7,2)` | 否 | 无 | CHECK | 课程总课时 |
| `course_status` | `VARCHAR(20)` | 否 | `草稿` | 联合索引 | 草稿、已上架、已下架或已归档 |
| `created_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` |  | 创建时间 |
| `updated_at` | `DATETIME(3)` | 否 | 当前时间并自动更新 |  | 更新时间 |

约束、索引与外键：

- `chk_course_price`：`price >= 0`；`chk_course_total_hours`：`total_hours > 0`。
- `chk_course_status`：`course_status IN ('草稿', '已上架', '已下架', '已归档')`。
- `idx_course_teacher (teacher_id)`。
- `idx_course_category_status (category, course_status)`。
- `fk_course_teacher (teacher_id) REFERENCES user_info(user_id) ON DELETE RESTRICT ON UPDATE CASCADE`。

## 4. `order_info` — 课程报名订单表

`user_id` 是购买者，`learner_user_id` 是实际学习者；学生本人购买时二者相同。

| 字段 | 类型 | 可空 | 默认值 | 键/索引 | 说明 |
|---|---|---:|---|---|---|
| `order_id` | `VARCHAR(50)` | 否 | 无 | PK | 订单业务 ID |
| `user_id` | `VARCHAR(50)` | 否 | 无 | FK、联合索引 | 购买者用户 ID |
| `learner_user_id` | `VARCHAR(50)` | 否 | 无 | FK、联合索引 | 实际学员用户 ID |
| `course_id` | `VARCHAR(50)` | 否 | 无 | FK、联合索引 | 报名课程 ID |
| `total_amount` | `DECIMAL(12,2)` | 否 | 无 | CHECK | 订单应付金额 |
| `currency` | `CHAR(3)` | 否 | `CNY` |  | ISO 4217 币种代码，首期使用 CNY |
| `study_goal` | `VARCHAR(500)` | 是 | `NULL` |  | 学习目标 |
| `expected_finish_days` | `SMALLINT UNSIGNED` | 是 | `NULL` | CHECK | 预期完成天数 |
| `payment_account_hash` | `CHAR(64)` | 是 | `NULL` | 联合索引 | 支付前可空；仅保存支付主体不可逆摘要 |
| `order_status` | `VARCHAR(20)` | 否 | `待支付` | 联合索引 | 订单状态 |
| `created_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` | 联合索引 | 下单时间 |
| `paid_at` | `DATETIME(3)` | 是 | `NULL` | 联合索引 | 支付成功时间 |
| `updated_at` | `DATETIME(3)` | 否 | 当前时间并自动更新 |  | 更新时间 |

约束：

- `chk_order_total_amount`：`total_amount >= 0`。
- `chk_order_expected_days`：`expected_finish_days IS NULL OR expected_finish_days > 0`。
- `chk_order_status`：`order_status IN ('待支付', '已支付', '已取消', '已关闭', '部分退款', '已退款')`。

索引与外键：

- `idx_order_user_paid (user_id, order_status, paid_at)`：R005 按购买者计算近 1 小时支付金额。
- `idx_order_course_created (course_id, order_status, created_at, learner_user_id)`：R001 按课程和实际学员计算报名聚集。
- `idx_order_payment_course (payment_account_hash, course_id, created_at)`：R001 查找共同支付主体。
- `idx_order_learner (learner_user_id, course_id)`：查询学员报名课程。
- `fk_order_buyer (user_id) REFERENCES user_info(user_id) ON DELETE RESTRICT ON UPDATE CASCADE`。
- `fk_order_learner (learner_user_id) REFERENCES user_info(user_id) ON DELETE RESTRICT ON UPDATE CASCADE`。
- `fk_order_course (course_id) REFERENCES course(course_id) ON DELETE RESTRICT ON UPDATE CASCADE`。

## 5. `learning_progress` — 学习进度表

每名学员在每门课程中只保存一条累计进度；明细学习事件不在本表重复保存。

| 字段 | 类型 | 可空 | 默认值 | 键/索引 | 说明 |
|---|---|---:|---|---|---|
| `progress_id` | `BIGINT UNSIGNED` | 否 | 自增 | PK | 进度记录 ID |
| `user_id` | `VARCHAR(50)` | 否 | 无 | FK、UNIQUE | 实际学员用户 ID |
| `course_id` | `VARCHAR(50)` | 否 | 无 | FK、UNIQUE | 课程 ID |
| `total_minutes` | `INT UNSIGNED` | 否 | `0` | CHECK | 累计学习分钟数，可因复习超过课程标准时长 |
| `completion_rate` | `DECIMAL(5,2)` | 否 | `0.00` | CHECK | 应用服务维护的课程完成率 |
| `last_active_at` | `DATETIME(3)` | 是 | `NULL` | 联合索引 | 最近学习时间，尚未开始时为空 |
| `completed_at` | `DATETIME(3)` | 是 | `NULL` |  | 首次达到完成标准的时间 |
| `created_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` |  | 创建时间 |
| `updated_at` | `DATETIME(3)` | 否 | 当前时间并自动更新 |  | 更新时间 |

约束、索引与外键：

- `uk_progress_user_course (user_id, course_id)`。
- `chk_progress_minutes`：`total_minutes >= 0`。
- `chk_progress_rate`：`completion_rate BETWEEN 0 AND 100`。
- `idx_progress_course_active (course_id, last_active_at, user_id)`。
- `fk_progress_user (user_id) REFERENCES user_info(user_id) ON DELETE RESTRICT ON UPDATE CASCADE`。
- `fk_progress_course (course_id) REFERENCES course(course_id) ON DELETE RESTRICT ON UPDATE CASCADE`。
- `total_minutes` 和 `completion_rate` 由同一个应用事务更新；数据库不跨表动态计算完成率。

## 6. `refund_request` — 退费申请表

`requested_amount` 是申请金额，`refund_amount` 是最终实际退款金额；后者在退款完成前允许为空。

| 字段 | 类型 | 可空 | 默认值 | 键/索引 | 说明 |
|---|---|---:|---|---|---|
| `refund_id` | `VARCHAR(50)` | 否 | 无 | PK | 退费申请业务 ID |
| `order_id` | `VARCHAR(50)` | 否 | 无 | FK、联合索引 | 原课程订单 ID |
| `requested_by_user_id` | `VARCHAR(50)` | 否 | 无 | FK、联合索引 | 发起申请的用户 ID |
| `reason` | `VARCHAR(500)` | 否 | 无 |  | 退费原因 |
| `study_minutes_before_refund` | `INT UNSIGNED` | 否 | 无 | CHECK | 提交申请时固化的学习分钟数快照 |
| `requested_amount` | `DECIMAL(12,2)` | 否 | 无 | CHECK | 用户申请退款金额 |
| `refund_amount` | `DECIMAL(12,2)` | 是 | `NULL` | CHECK | 实际退款金额 |
| `refund_status` | `VARCHAR(20)` | 否 | `待审核` | 联合索引 | 退费处理状态 |
| `requested_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` | 联合索引 | 申请时间 |
| `completed_at` | `DATETIME(3)` | 是 | `NULL` | 联合索引 | 退款成功或失败的完成时间 |
| `created_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` |  | 记录创建时间 |
| `updated_at` | `DATETIME(3)` | 否 | 当前时间并自动更新 |  | 记录更新时间 |

约束：

- `chk_refund_study_minutes`：`study_minutes_before_refund >= 0`。
- `chk_refund_requested_amount`：`requested_amount > 0`。
- `chk_refund_amount`：`refund_amount IS NULL OR (refund_amount >= 0 AND refund_amount <= requested_amount)`。
- `chk_refund_status`：`refund_status IN ('待审核', '审核中', '已批准', '已拒绝', '已取消', '退款成功', '退款失败')`。
- 应用层另外校验申请金额不超过订单可退余额，避免多次部分退款累计超额。
- 学习分钟快照写入后不可随当前进度更新。

索引与外键：

- `idx_refund_order_requested (order_id, requested_at)`。
- `idx_refund_status_completed (refund_status, completed_at, order_id)`：R012 筛选成功退款。
- `idx_refund_requester (requested_by_user_id, requested_at)`。
- `fk_refund_order (order_id) REFERENCES order_info(order_id) ON DELETE RESTRICT ON UPDATE CASCADE`。
- `fk_refund_requester (requested_by_user_id) REFERENCES user_info(user_id) ON DELETE RESTRICT ON UPDATE CASCADE`。

## 7. `blacklist_extra` — 风控黑名单表

该表属于风控基础数据，但保留题目指定名称。身份证和设备指纹不保存原文，应用层生成 HMAC-SHA256 后写入 `value`。

| 字段 | 类型 | 可空 | 默认值 | 键/索引 | 说明 |
|---|---|---:|---|---|---|
| `entry_id` | `BIGINT UNSIGNED` | 否 | 自增 | PK | 黑名单记录 ID |
| `type` | `VARCHAR(20)` | 否 | 无 | UNIQUE | 用户ID、学号、身份证、设备指纹或直播账号 |
| `value` | `VARCHAR(200)` | 否 | 无 | UNIQUE | 规范化匹配值；敏感类型存 HMAC 摘要 |
| `value_masked` | `VARCHAR(200)` | 是 | `NULL` |  | 供界面展示的脱敏值 |
| `reason` | `VARCHAR(500)` | 否 | 无 |  | 加入原因 |
| `status` | `VARCHAR(20)` | 否 | `启用` | 联合索引 | 启用或停用 |
| `expire_at` | `DATETIME(3)` | 是 | `NULL` | 联合索引 | 为空表示永久有效 |
| `created_by` | `VARCHAR(50)` | 否 | `system` |  | 操作人或系统标识，不关联业务用户表 |
| `created_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` |  | 创建时间 |
| `updated_at` | `DATETIME(3)` | 否 | 当前时间并自动更新 |  | 更新时间 |
| `deleted_at` | `DATETIME(3)` | 是 | `NULL` | 联合索引 | 软删除时间 |

约束与索引：

- `uk_blacklist_type_value (type, value)`：同一对象只保留一条记录，重新加入时恢复并更新原记录。
- `chk_blacklist_type`：`type IN ('用户ID', '学号', '身份证', '设备指纹', '直播账号')`。
- `chk_blacklist_status`：`status IN ('启用', '停用')`。
- `idx_blacklist_active (status, expire_at, deleted_at)`。
- 这是多目标逻辑匹配表，不设置指向多张业务表的物理外键。

## 8. `education_credential` — 学历认证表

身份证原文由应用加密后存储，摘要用于去重或精确匹配，脱敏值用于人工审核页面。

| 字段 | 类型 | 可空 | 默认值 | 键/索引 | 说明 |
|---|---|---:|---|---|---|
| `credential_id` | `VARCHAR(50)` | 否 | 无 | PK | 认证申请业务 ID |
| `user_id` | `VARCHAR(50)` | 否 | 无 | FK、联合索引 | 申请认证的用户 ID |
| `id_card_ciphertext` | `VARBINARY(512)` | 否 | 无 |  | 身份证号密文，密钥不存数据库 |
| `id_card_hash` | `CHAR(64)` | 否 | 无 | 索引 | 身份证号 HMAC-SHA256 摘要 |
| `id_card_masked` | `VARCHAR(20)` | 否 | 无 |  | 身份证脱敏展示值 |
| `submitted_education_level` | `VARCHAR(30)` | 否 | 无 |  | 用户申报学历 |
| `authoritative_education_level` | `VARCHAR(30)` | 是 | `NULL` |  | 权威源返回学历；无记录或异常时为空 |
| `verify_status` | `VARCHAR(20)` | 否 | `待核验` | 联合索引 | 待核验、匹配、不匹配、无记录或系统异常 |
| `mismatch_reason` | `VARCHAR(100)` | 是 | `NULL` |  | 身份或学历不匹配原因 |
| `verify_source` | `VARCHAR(50)` | 是 | `NULL` |  | 权威数据源标识 |
| `verify_reference_id` | `VARCHAR(100)` | 是 | `NULL` |  | 外部核验流水号 |
| `submitted_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` | 联合索引 | 提交时间 |
| `verified_at` | `DATETIME(3)` | 是 | `NULL` | 联合索引 | 核验完成时间 |
| `created_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` |  | 创建时间 |
| `updated_at` | `DATETIME(3)` | 否 | 当前时间并自动更新 |  | 更新时间 |

约束、索引与外键：

- `chk_credential_status`：`verify_status IN ('待核验', '匹配', '不匹配', '无记录', '系统异常')`。
- `idx_credential_user_submitted (user_id, submitted_at)`。
- `idx_credential_status (verify_status, verified_at)`。
- `idx_credential_id_hash (id_card_hash)`。
- `fk_credential_user (user_id) REFERENCES user_info(user_id) ON DELETE RESTRICT ON UPDATE CASCADE`。
- “无记录”进入人工审核；“系统异常”进入重试，不作为用户风险命中。

## 9. `live_reward` — 直播打赏流水表

每笔打赏、退款、撤销或冲正分别记录一行，金额始终为正，通过 `transaction_type` 确定净额正负方向。

| 字段 | 类型 | 可空 | 默认值 | 键/索引 | 说明 |
|---|---|---:|---|---|---|
| `reward_id` | `VARCHAR(50)` | 否 | 无 | PK | 打赏交易或调整流水 ID，同时承担幂等键作用 |
| `live_session_id` | `VARCHAR(50)` | 否 | 无 | 联合索引 | 直播场次 ID |
| `user_id` | `VARCHAR(50)` | 否 | 无 | FK、联合索引 | 打赏账号对应的内部用户 ID |
| `reward_account_id` | `VARCHAR(50)` | 否 | 无 | 联合索引 | 直播平台打赏账号 ID |
| `original_reward_id` | `VARCHAR(50)` | 是 | `NULL` | FK、索引 | 退款、撤销或冲正对应的原打赏流水 |
| `transaction_type` | `VARCHAR(20)` | 否 | `打赏` | 联合索引 | 打赏、退款、撤销或冲正 |
| `amount` | `DECIMAL(12,2)` | 否 | 无 | CHECK | 本笔流水的正数金额 |
| `reward_status` | `VARCHAR(20)` | 否 | `处理中` | 联合索引 | 处理中、成功或失败 |
| `rewarded_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` | 联合索引 | 业务发生时间 |
| `created_at` | `DATETIME(3)` | 否 | `CURRENT_TIMESTAMP(3)` |  | 创建时间 |
| `updated_at` | `DATETIME(3)` | 否 | 当前时间并自动更新 |  | 更新时间 |

约束：

- `chk_reward_type`：`transaction_type IN ('打赏', '退款', '撤销', '冲正')`。
- `chk_reward_status`：`reward_status IN ('处理中', '成功', '失败')`。
- `chk_reward_amount`：`amount > 0`。
- 应用层保证调整流水必须填写 `original_reward_id`，且累计调整金额不超过原打赏金额。

索引与外键：

- `idx_reward_account_session (reward_account_id, live_session_id, reward_status, transaction_type, rewarded_at)`：计算 R018 单场净额。
- `idx_reward_user_time (user_id, rewarded_at)`。
- `idx_reward_original (original_reward_id)`。
- `fk_reward_user (user_id) REFERENCES user_info(user_id) ON DELETE RESTRICT ON UPDATE CASCADE`。
- `fk_reward_original (original_reward_id) REFERENCES live_reward(reward_id) ON DELETE RESTRICT ON UPDATE CASCADE`。

## 确认记录

| 批次 | 已确认内容 |
|---|---|
| 第一组 | `snake_case`；`user_info` 采用业务字符串主键；启用多设备历史；用户删除采用 `RESTRICT` |
| 第二组 | `course.total_hours` 使用小数课时；订单区分购买者与学员；保留 CNY 币种字段；用户、老师和课程外键采用 `RESTRICT` |
| 第三组 | 每名学员每门课程保存一条累计进度；完成率由应用维护；退费区分申请金额和实际金额；申请时固化学习分钟快照 |
| 后续自主决策 | 黑名单敏感值使用 HMAC；学历身份证使用密文、摘要和脱敏值三份表达；直播打赏采用可冲正流水模型 |
