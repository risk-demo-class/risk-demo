# AI_Risk 项目文件功能作用说明

项目路径：

```text
G:\day10 吴玉祥\尚硅谷大模型项目之风控系统\3.代码\AI_Risk
```

本文档用于说明原始完整风控项目中各类文件的实现功能和作用，方便后续参考其架构重新设计旅游行业风控系统。

旅游行业项目生成时原则是：文件名、目录层级、核心职责尽量贴合参考项目，业务含义替换为旅游行业。这样后续查阅时可以直接按参考项目路径定位，不需要重新学习一套结构。

## 一、项目整体分层

该项目可以理解为四层结构：

```text
页面/接口层 routers + templates
  -> 服务编排层 service
  -> 风控引擎层 engine
  -> 数据持久层 models + sql
```

核心风控执行链路：

```text
app/routers/risk.py
 -> app/service/event.py
 -> app/service/validator.py
 -> app/service/case.py
 -> app/engine/decision.py
 -> app/engine/feature.py
 -> app/engine/rule.py
 -> app/engine/ml_model.py
 -> app/models_risk.py
```

### `feature.py` 的作用

该文件负责把数据库中的原始业务数据转换成风控可用的特征。旅游版继续保留参考项目的三段函数结构：

```text
compute_user_features()
compute_order_features()
compute_address_features()
compute_all_features()
```

旅游版的 `address_features` 实际表示目的地、酒店城市、航线到达地等位置风险特征，命名前缀仍用 `addr_*`，这样可以少改 `decision.py` 的特征快照分类逻辑。

旅游版特征示例：

| 特征类型 | 示例 |
|---|---|
| 用户特征 | 注册天数、实名状态、近 7 天订单数、近 90 天退款率、拒签次数、同设备账号数、同支付账号 1 小时订单数。 |
| 订单特征 | 订单金额、旅客数、距出发天数、行程天数、是否跨境、是否凌晨下单、同航班 1 小时票数、旅客匹配率。 |
| 目的地特征 | 目的地风险分、近 7 天同目的地下单次数、近 30 天不同国家数、是否新目的地、同航线 1 小时订单数。 |

原始电商版特征示例：

| 特征类型 | 示例 |
|---|---|
| 用户特征 | 用户总订单数、30 天订单数、7 天订单数、总消费金额、平均订单金额、退款次数、售后次数、投诉次数等。 |
| 订单特征 | 订单金额、商品数量、SKU 数量、优惠金额、优惠比例、支付间隔、是否夜间下单等。 |
| 地址特征 | 地址数量、省份数量、是否新地址等。 |

### `rule.py` 的作用

该文件负责规则判断：

```text
读取启用规则
 -> 解析 rule_condition
 -> 从 features 中取对应特征值
 -> 按操作符比较
 -> 返回命中的规则列表
```

### `decision.py` 的作用

该文件是风控主引擎，核心流程包括：

```text
1. 构建上下文
2. 创建 risk_event
3. 计算特征
4. 保存 risk_feature 快照
5. 加载并匹配规则
6. 计算规则分
7. 融合机器学习分
8. 判断风险等级和决策
9. 保存 risk_assessment
10. 必要时创建 risk_case
11. 更新 risk_user_profile
12. 返回 RiskCheckResponse
```

### `event.py` 的主流程

```text
process_event()
  -> validate_risk_check_request()
  -> _enrich_request()
  -> _check_all_blacklists()
  -> run_risk_check()
```

其中黑名单属于前置拦截，如果命中黑名单，会直接返回拒绝结果，不再继续执行完整规则引擎。

旅游版 `event.py` 保持同样 4 步，只替换业务补全逻辑：

| 步骤 | 旅游版处理 |
|---|---|
| 业务实体校验 | 按 `旅游下单 / 机票预订 / 酒店预订 / 签证申请 / 支付 / 售后申请 / 投诉 / 出行前核验` 校验 source_id。 |
| 自动补全参数 | 从机票、酒店、签证、售后、投诉表反查 `order_id`，并补充目的地、旅客证件、支付账号、设备等事件数据。 |
| 黑名单前置拦截 | 检查用户、手机号、护照号、身份证号、支付账号、设备指纹、IP、订单。 |
| 调用决策引擎 | 继续调用 `run_risk_check()`，不改变 7 步主流程。 |

旅游版 `validator.py` 的 source_id 派发表：

| 事件类型 | source_id 指向 |
|---|---|
| `旅游下单` | `OrderInfo.order_id` |
| `机票预订` | `BookingFlight.booking_id` |
| `酒店预订` | `BookingHotel.booking_id` |
| `签证申请` | `VisaApplication.visa_id` |
| `支付` | `OrderInfo.order_id` |
| `售后申请` | `TravelRefund.refund_id` |
| `投诉` | `TravelComplaint.complaint_id` |
| `出行前核验` | `OrderInfo.order_id` |

## 十六、学习这个项目时的推荐阅读顺序

建议按下面顺序理解：

```text
1. run_app.py
2. app/api.py
3. app/routers/risk.py
4. app/service/event.py
5. app/service/validator.py
6. app/engine/decision.py
7. app/engine/feature.py
8. app/engine/rule.py
9. app/models_business.py
10. app/models_risk.py
11. sql/init_business_tables.sql
12. sql/init_risk_tables.sql
13. templates/*.html + static/app.js
14. docker/docker-compose.yml + docker/Dockerfile + docker/nginx.conf
```

其中最关键的是：

```text
event.py 负责接收和编排事件
validator.py 负责业务合法性校验
feature.py 负责从数据库计算特征
rule.py 负责规则命中
decision.py 负责评分、决策和落库
models_risk.py 负责风控结果存储结构
```
