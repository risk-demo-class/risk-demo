# AI_Risk 启动运行指南（从零到跑通）

> 本文档基于 2026-08-10 实际跑通的过程整理。适用于：新机器 / 新环境，从安装依赖到服务启动的完整步骤。

---

## 一、前置条件（需要先装好）

| 组件 | 版本 | 用途 |
|---|---|---|
| Python | 3.12（3.11 也可） | 运行环境 |
| uv | 0.11+ | 依赖管理（比 pip 快，推荐） |
| MySQL | 8.0+ | 数据库（本机已用 conda 自带 mysqld） |

检查命令：

```bash
python3 --version      # 需 3.11 ~ 3.12
uv --version
mysql --version        # 客户端，看有没有装
```

> 注意：项目 `uv/pyproject.toml` 要求 `>=3.11,<3.13`，**不要用 Python 3.13**。

## 二、首次启动（完整流程）

### 步骤 1：创建虚拟环境 + 安装依赖

在项目根目录执行：

```bash
uv venv .venv --python 3.12
uv pip install -r uv/requirements-uv.txt
```

> 约 89 个包。若机器没装 uv，先 `curl -LsSf https://astral.sh/uv/install.sh | sh`。
> 不想用 uv 也可以用 pip：`python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt`

### 步骤 2：启动 MySQL

本机 MySQL 是 conda 自带的服务端（`mysqld`），**首次需要初始化数据目录**：

```bash
# 1. 初始化数据目录（只需第一次，root 密码为空）
mkdir -p ~/mysql-data
mysqld --initialize-insecure --basedir=/opt/anaconda3 --datadir="$HOME/mysql-data"

# 2. 启动服务
nohup mysqld --basedir=/opt/anaconda3 --datadir="$HOME/mysql-data" \
  --port=3306 --socket=/tmp/mysql.sock --bind-address=127.0.0.1 \
  --character-set-server=utf8mb4 --collation-server=utf8mb4_0900_ai_ci \
  > "$HOME/mysql-data/mysqld.log" 2>&1 &

# 3. 验证
mysqladmin --socket=/tmp/mysql.sock ping   # 应输出: mysqld is alive
```

**设置 root 密码为 123321**（项目配置默认值，可选其他值但需同步改 `.env`）：

```bash
mysql --socket=/tmp/mysql.sock -u root -e \
  "ALTER USER 'root'@'localhost' IDENTIFIED BY '123321'; \
   CREATE USER IF NOT EXISTS 'root'@'127.0.0.1' IDENTIFIED BY '123321'; \
   GRANT ALL PRIVILEGES ON *.* TO 'root'@'127.0.0.1' WITH GRANT OPTION; \
   FLUSH PRIVILEGES;"
```

> 经验：MySQL 8.4 默认不支持 `mysql_native_password`，直接 `IDENTIFIED BY`（默认 `caching_sha2_password`），pymysql 1.1 支持，无需改插件。

### 步骤 3：创建 `.env`（重要）

> ⚠️ **不要复制 `docker/.env.example`**！那是 Docker 生产模板，含 `MYSQL_ROOT_PASSWORD` / `APP_PORT` 等字段，本项目 `app/config.py` 的 Settings 是 `extra_forbidden`，多了会启动直接 FAIL。

在项目根目录手写 `.env`（只放 Settings 认的字段）：

```ini
# .env (项目根目录)
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=123321
DB_NAME=ecs
TEST_DB_NAME=ecs_test

# LLM (阿里云百炼, 不填则 Agent 功能降级, 其余功能不受影响)
LLM_API_KEY=
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL_NAME=qwen-plus

# XGBoost (默认 True, 没模型自动降级纯规则)
XGB_ENABLED=True
```

### 步骤 4：初始化数据库

```bash
uv run python scripts/init_db.py --yes
```

> 默认 `--reset` 删库重建（首次装没事）。会建 26 张表 + 灌业务数据 + 30 条风控规则。
> 老库想保留数据用 `--keep-data`。

### 步骤 5：启动服务

```bash
uv run python run_app.py
```

启动前自动 6 步自检，看到 `汇总: 6 OK / 0 WARN / 0 FAIL` 后进入服务。

> 后台运行（演示用）：
> ```bash
> echo "" | nohup uv run python run_app.py > logs/startup.log 2>&1 &
> ```
> 自检有 WARN 时会等回车确认，所以用管道喂一个空行。

### 步骤 6：验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/     # 200
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/docs # 200
```

浏览器打开：
- 仪表盘：http://localhost:8000/
- API 文档：http://localhost:8000/docs

## 三、测试风控检查（验证全链路）

```bash
# 先取一个真实订单
ORDER_ID=$(mysql --socket=/tmp/mysql.sock -u root -p123321 ecs -N -e "SELECT order_id FROM order_info LIMIT 1" 2>/dev/null)
USER_ID=$(mysql --socket=/tmp/mysql.sock -u root -p123321 ecs -N -e "SELECT user_id FROM order_info WHERE order_id='$ORDER_ID' LIMIT 1" 2>/dev/null)

curl -s -X POST http://localhost:8000/api/risk/check \
  -H "Content-Type: application/json" \
  -d "{\"event_type\":\"下单\",\"source_id\":\"$ORDER_ID\",\"user_id\":\"$USER_ID\",\"order_id\":\"$ORDER_ID\"}"
```

正常会返回 `final_score` / `risk_level` / `decision` / `triggered_rules` 等字段。示例订单 `ORD_TEST_001` 不在库里，会报"订单ID不存在"，属正常。

## 四、日常使用

### 启动 / 停止

```bash
# 启动
uv run python run_app.py

# 停止 (后台启动时)
pkill -f run_app.py
```

### 跑测试

```bash
uv run pytest tests/          # 329 个用例, ~30 秒
uv run pytest tests/test_risk_decision.py -v
```

### 看日志

```bash
tail -f logs/app.log          # 统一日志 (stdout + 文件)
grep ERROR logs/app.log
```

### 造数据 / 训练模型（可选，增强功能）

纯规则模式已能用，以下为开启 ML 双轨：

```bash
# 1. 生成风险用户样本
uv run python scripts/gen_risky_users.py

# 2. 造训练评估数据 (--balance-pos 保证正例比例 20%+)
uv run python scripts/gen_risk_data.py --count 200 --balance-pos

# 3. 训练 XGBoost 模型 → 生成 app/engine/xgb_model.json
uv run python scripts/train_xgb_model.py

# 4. 造带日期的仪表盘趋势数据
uv run python scripts/gen_risk_data_with_dates.py --days 7 --per-day 20
```

训练后重启服务，自检会显示 `[OK] XGBoost 模型已加载`，风控改为"规则 + ML"双轨加权融合。

## 五、踩过的坑（FAQ）

| 症状 | 原因 | 解决 |
|---|---|---|
| 自检 FAIL: `Extra inputs are not permitted` | `.env` 复制了 docker 模板 | 用本文档步骤 3 的 `.env`，只放 Settings 字段 |
| `No module named 'greenlet'`（scheduler 报错） | SQLAlchemy 异步需要 greenlet，requirements 漏声明 | `uv pip install greenlet`；已补进 `requirements.txt` / `uv/requirements-uv.txt` |
| `Plugin 'mysql_native_password' is not loaded` | MySQL 8.4 移除了该插件 | 用默认 `IDENTIFIED BY`（caching_sha2_password） |
| `mysqld: Can't connect` / socket 找不到 | MySQL 没启动 | 步骤 2 启动命令；socket 在 `/tmp/mysql.sock` |
| 启动卡住不动 | 后台运行时 WARN 在等回车 | `echo "" \| nohup ... &` 喂空行 |
| 端口 8000 被占 | 已有实例 | `pkill -f run_app.py` 或改 `APP_PORT` 环境变量 |
| `ModuleNotFoundError: No module named 'app'` | 不在项目根运行 | 必须在项目根目录执行命令 |
| XGBoost 自检 WARN | 没训模型 | 业务不受影响（纯规则），想用 ML 跑步骤四 |
