# CONTEXT — 银行信贷风控系统

> 本文件是**术语表**（Ubiquitous Language），不含实现细节。改造过程中持续更新。
> 背景：由电商风控系统全量替换而来，引擎层（规则+ML 双轨、案件、告警、黑名单）复用。

## 领域定位

- **银行信贷风控**：以贷款申请审批为主线，叠加反欺诈、信用风险、反洗钱合规三个风险维度。

## 核心术语

| 术语 | 定义 |
|---|---|
| **客户** (Customer) | 银行的个人/企业服务对象。系统的首要实体，用 `customer_id` 标识。（不叫"用户 user"，电商遗留） |
| **贷款申请** (Loan Application) | 客户提交贷款申请的动作与记录。事件类型之一，风控在线的进件入口。 |
| **放款** (Disbursement) | 审批通过后资金发放环节，需复核。事件类型之一。 |
| **还款** (Repayment) | 客户偿还贷款本金/利息。事件类型之一，语义上覆盖"还款/逾期监测"（贷后）。 |
| **客户投诉** (Complaint) | 客户对银行服务/产品的投诉，纠纷信号。事件类型之一。 |
| **信贷生命周期** | 进件（贷款申请）→ 放款 → 贷后（还款/逾期）→ 服务（投诉）。 |

## 事件类型（4 个，与引擎枚举对齐）

1. 贷款申请（原"下单"）
2. 放款（原"支付"）
3. 还款（原"售后申请"，语义含逾期监测）
4. 客户投诉（原"物流投诉"）

## 风险维度（规则分类，6 大场景）

欺诈风险 / 信用风险 / 反洗钱 / 账户风险 / 贷后风险 / 合规风险

## 特征域（25 维，3 类前缀）

- `cust_*` 客户维度（14）：多头借贷、逾期史、履约率等
- `loan_*` 申请维度（8）：申请金额、负债率、收入负债比等
- `dev_*`  设备/网络维度（3）：设备数、IP 跨省、新设备

## 决策语义

- 评分 0-100 → 等级 低/中/高/极高 → 决策 通过/标记/人工审核/拒绝
- 双轨融合：规则分 α + XGBoost 分 β（sigmoid 校准）
- 一票否决：命中"极高"规则强制拒绝
- 案件：人工审核/拒绝才建案，自动拒绝直接结案

## 模型语义（已确认）

- XGBoost 标签 = **PD 违约概率**：0=正常履约，1=逾期违约（贷后结果）。
- 训练正例来源：有逾期记录的客户（高风险画像 → 逾期 → 违约标签 1）。
- 解释：XGBoost 为信用评分模型（A 卡），规则引擎为反欺诈+合规策略，双轨融合输出授信决策。
- 决策映射逻辑（概率→4 档）复用，仅标签来源与语义命名切换。

## 契约取舍（已确认）

- 请求字段保留引擎字段名 `order_id` / `receive_id`，**语义**切换为 `loan_id`（贷款申请ID）/ `contact_id`（联系信息ID）。
- 动机：引擎层决策代码零改动；字段语义由文档/前端/校验层表达。

- 前端品牌：虚构银行名「华信银行 · 信贷风控平台」。
- 黑名单类型（已确认）：**客户 / 手机号 / 地址 / 设备** 4 类（设备为反欺诈关键维度，与 dev_* 特征域呼应）。
