## 一、业务计划书

### 1. 项目定位

本项目面向职业技能在线教育平台，保护报名收入、退款权益以及学历/身份认证可信度。它不评价学习成绩，不建设考试防作弊、内容审核、直播打赏或真实支付渠道。

每个受控事件必须做到：实时判定、可解释、可回放、可人工复核、可审计、可告警、可由规则和模型共同评估。

### 2. 角色与权限

| 角色 | 可执行动作 | 权限边界 |
|---|---|---|
| 学员/付款人 | 报名、学习、退款、提交认证 | 仅查看本人结果；不可见规则、特征、模型分数 |
| 课程运营/教师 | 维护课程与学习交付 | 不可审核风险案件 |
| 风控运营 | 查评估、处理案件、维护规则和黑名单 | 只看脱敏业务数据；不可改原始事件、特征、评估 |
| 风控管理员 | 发布/回滚规则、处理高权限黑名单、处置告警 | 所有动作必须进入审计日志 |
| 数据/模型人员 | 离线训练、评估、发布影子模型 | 只使用脱敏训练数据；不可直接改线上案件结论 |
| 系统任务 | 超时关案、告警、模型加载 | 使用 `system` 身份写审计 |

### 3. 三类核心教育风险事件

#### 3.1 课程报名

**风险：** 同设备批量新账号、薅优惠、异常高频/高额报名、黑名单主体再次报名。

**证据：** 学员、课程、报名、优惠、支付状态、设备哈希、渠道/IP（后续接入）。

| 规则 | 信号 | 处置 |
|---|---|---|
| EDU-ENR-001 | 7 日同设备关联新账号达到阈值 | 人工审核或拒绝 |
| EDU-ENR-002 | 新账号短时多次报名或累计金额异常 | 人工审核 |
| EDU-ENR-003 | 同课程短时集中新账号报名 | 标记/人工审核 |
| EDU-ENR-004 | 学员、证件哈希、设备哈希撞黑 | 拒绝（一票否决） |

#### 3.2 退费申请

**风险：** 极低学习投入后频繁退款、占用资源套利、持续高额退款。

**证据：** 原报名、退款单、退款前学习分钟数、完成率、90 天退款次数/金额、退款原因码。

| 规则 | 信号 | 处置 |
|---|---|---|
| EDU-REF-001 | 学习不足 5 分钟即退款 | 人工审核，不自动拒绝 |
| EDU-REF-002 | 90 天退款次数达到阈值 | 标记/人工审核 |
| EDU-REF-003 | 退款金额高且完成率异常低 | 人工审核 |
| EDU-REF-004 | 黑名单主体请求退款 | 冻结/拒绝，按退款政策处理 |

#### 3.3 学历/身份认证

**风险：** 伪造材料、多次失败试探、黑名单主体获得课程权益或证书资格。

**证据：** 认证类型、学号/证件哈希、认证结果、失败原因码、提交时间、关联设备。

| 规则 | 信号 | 处置 |
|---|---|---|
| EDU-VER-001 | 30 天连续认证失败达到阈值 | 人工审核 |
| EDU-VER-002 | 证件/学号哈希撞黑 | 拒绝（一票否决） |
| EDU-VER-003 | 多账号复用同一证件哈希或设备 | 人工审核/拒绝 |

### 4. 统一风控流程

```text
事件接入 → 业务归属校验 → 上下文补全 → 黑名单短路
        → 特征计算 → 特征快照 → 规则匹配 → 模型预测
        → 决策融合 → 事件/评估/案件/画像/审计落库
```

决策统一为 `通过 / 标记 / 人工审核 / 拒绝`。黑名单与确认型高危规则可以一票否决，模型不得把一票否决降级为放行。

原始事件、特征快照、规则命中和评估结果只可新增、不可被人工覆盖；人工审核仅改变案件状态，并产生完整操作审计。

### 5. 数据与隐私

| 数据域 | 表/对象 | 生产约束 |
|---|---|---|
| 学员 | `student` | 学号哈希、实名状态、姓名脱敏 |
| 课程 | `course` | 课程、类目、价格、课时、教师 |
| 报名 | `enrollment` | 学员、课程、实付/优惠、时间、状态 |
| 学习 | `learning_progress` | 学习分钟、完成率、最后活跃 |
| 退款 | `refund_request` | 原报名、金额、原因、退款前学习数据 |
| 认证 | `credential_verification` | 认证类型、证件哈希、状态、失败原因 |
| 设备 | `device_binding` | 设备指纹哈希、首次/最后活跃 |
| 风控 | `risk_*` | 事件、特征、评估、案件、规则、黑名单、画像、告警、审计 |

禁止保存明文身份证号、明文设备指纹、银行卡信息。黑名单与模型训练只使用业务必要的哈希和脱敏字段。

### 6. 案件与运营闭环

```text
待审核 → 审核中 → 已通过 / 已拒绝 / 已关闭
待审核 → 已通过 / 已拒绝 / 已关闭
终态不可再改
```

审核必须记录审核人、意见、时间、证据依据。拒绝并加黑必须同一事务提交。超时案件需由系统自动关闭或升级告警，不能静默堆积。

### 7. 模型策略

1. 模型是规则补充，不能取代确认型规则和人工审核。
2. 标签来自已结案案件、确认欺诈和申诉结果，不能只把“规则命中”当真值。
3. 训练与验证必须按时间切分，防止数据泄漏；特征版本与模型版本绑定。
4. 离线评估输出 AUC、PR-AUC、F1、Precision、Recall、混淆矩阵及三场景分桶指标。
5. 上线先影子评分，再灰度融合；持续监控分数分布、拒绝率、审核率、规则命中率和审核后坏账率。

## 二、源码对齐架构计划

### 1. 必须保留的旧项目形态

```text
MySQL 8.0 + FastAPI App + Nginx
        ↓
app/routers → app/service → app/engine → app/models
        ↓
sql/ 初始化与迁移 → scripts/ 运维与训练 → tests/ MySQL 集成测试
```

旧项目的关键能力及教育替换如下：

| 旧项目模块 | 教育版实现 |
|---|---|
| `docker/docker-compose.yml` | MySQL、FastAPI、Nginx 三服务保持不变，仅修改教育库名/容器名/环境变量 |
| `app/database.py` | 保留异步 `AsyncSession`、aiomysql、连接池、显式 rollback/close |
| `sql/init_business_tables.sql` | 电商用户/订单/售后替换为学员/报名/学习/退款/认证/设备 |
| `sql/init_risk_tables.sql` | 保留规则、黑名单、事件、特征、评估、案件、画像、告警、审计 |
| `service/event.py` | 教育四步管道：校验→补全→黑名单→七步引擎 |
| `engine/feature.py` | 学员/报名/学习/退款/认证/设备特征 |
| `engine/decision.py` | 七步事件、特征快照、规则、模型融合、建案、画像更新 |
| `routers` | 保留 risk/rule/case/blacklist/assessment/dashboard/alert/profile/pages |
| `templates` | 保留运营后台结构，仅替换教育术语、字段、接口和权限状态 |
| `scripts/train_xgb_model.py` | 改为教育特征、教育标签、教育验收阈值 |

### 2. 目标目录

```text
education_risk_production/
├─ app/
│  ├─ routers/ service/ engine/
│  ├─ models_business.py  models_risk.py  schemas.py
│  ├─ database.py  config.py  scheduler.py  logging_config.py
├─ sql/ scripts/ docker/ templates/ static/ tests/ docs/
└─ run_app.py
```

### 3. SQL 与迁移

业务表按外键顺序建立：基础维度 → 学员/设备 → 课程/报名 → 学习/退款/认证。

风控表保留：`risk_rule`、`risk_blacklist`、`risk_event`、`risk_feature`、`risk_assessment`、`risk_case`、`risk_user_profile`、`risk_alert`、`risk_action_log`。

- `init_all.sql`：业务 DDL → 风控 DDL → 教育基础数据 → 教育规则数据。
- 每次字段和索引调整必须新增幂等 migration，包含回滚 SQL。
- 所有 DDL 与 migration 必须在独立 MySQL 测试库验证；不得以 SQLite 通过替代。

## 三、生产级代码实施任务

### 阶段 A：基础设施与数据层

#### 任务 1：生产工程骨架

复制旧项目目录与 uv 依赖管理形态，创建新的教育生产目录；不修改 `AI_Risk`，不继续以当前 SQLite 原型为运行底座。

**验收：** 环境可重复创建；所有教育模块独立 import；有完整源码映射文档。

#### 任务 2：Docker、MySQL、配置、自检

复用旧 `docker/`、`run_app.py`、`config.py`、`database.py` 的生产模式。

**验收：** `docker compose up -d` 启动 MySQL/App/Nginx；MySQL 健康后 App 才启动；`.env` 不进 Git；启动前检查依赖、数据库、端口、DDL、模型。

#### 任务 3：教育 DDL 与迁移

实现业务表、风控表、外键、索引、状态枚举、初始化 SQL 和增量迁移。

**验收：** 空库可初始化；升级库可迁移；迁移可回滚；关键唯一约束、外键、软删、索引都有 MySQL 集成测试。

#### 任务 4：ORM、Schema 与教育种子数据

实现异步 ORM、请求/响应 Schema 和覆盖正常/审核/拒绝的教育数据。

**验收：** 三场景数据可通过 MySQL 关联查询；输入参数、分页、状态机均由 Schema 校验。

**检查点 A：** Docker 三服务健康；DDL/MySQL 集成测试通过；运行环境无 SQLite。

### 阶段 B：实时风控引擎

#### 任务 5：教育四步事件服务

报名、退款、认证分别校验来源存在、用户归属、关联实体完整性，并补齐课程/学习/证件/设备上下文。

**验收：** 三种事件的越权、缺失来源、无效关联全部返回规范错误；黑名单短路策略可审计。

#### 任务 6：教育七步引擎与特征快照

保留旧项目七步结构；对报名、退款、认证使用显式处理器映射，避免业务分支散落在共享逻辑中。

**验收：** 非短路事件必写事件、特征、评估；高风险建案件；特征列清单是线上与训练的唯一事实来源。

#### 任务 7：规则版本、黑名单与审计

规则支持创建、编辑、启停、优先级、版本发布、软删和回滚；黑名单支持去重、失效、软删。

**验收：** 非法 JSON 条件/字段/运算符被拒绝；拒绝加黑和审核状态同事务；所有管理动作写 `risk_action_log`。

#### 任务 8：案件、评估、画像闭环

实现案件详情回放、状态机、审核记录、自动拒绝、案件去重、超时关闭和画像更新。

**验收：** 详情可回放事件、特征、规则、模型版本、评估、操作历史；列表分页且无 N+1。

**检查点 B：** MySQL 集成测试覆盖正常报名、共享设备、低学习退款、连续认证失败、黑名单拒绝和案件审核。

### 阶段 C：模型、运营与发布

#### 任务 9：教育模型训练和影子发布

迁移旧项目 XGBoost 加载、训练、评估、融合、降级能力，替换为教育特征与真实标签策略。

**验收：** 训练/验证按时间分割；特征列一致；输出完整离线指标；模型文件包含版本、数据窗、标签定义和指标；先影子运行。

#### 任务 10：仪表盘、告警、调度与前端

保留旧项目页面路由、案件工作台、规则/黑名单页、评估历史、Dashboard、Alert、Scheduler。

**验收：** 所有统计来自 MySQL 聚合；显示事件量、案件积压、规则命中、模型分布、告警；后台任务幂等并写日志。

#### 任务 11：权限、安全和可观测性

增加后台角色权限、脱敏响应、结构化日志、健康检查、错误指标。

**验收：** 学员不可访问后台；日志不含敏感值；页面动态内容安全渲染；浏览器控制台无错误。

#### 任务 12：CI、压测、发布与回滚演练

建立测试门禁、镜像构建、部署手册、备份恢复、迁移/规则/模型回滚流程。

**验收：** 空环境一键部署；可回滚 SQL、规则、模型、镜像；压测与容量假设有记录。

## 四、测试与生产验收

| 层级 | 验证内容 | 环境 |
|---|---|---|
| 单元测试 | 规则、评分融合、状态机、特征纯函数 | 无数据库 |
| MySQL 集成测试 | 事务、外键、迁移、Router/Service/Engine | 独立 `education_risk_test` |
| 契约测试 | API Schema、错误码、分页、权限 | FastAPI + MySQL |
| 浏览器测试 | 仪表盘、规则、案件、黑名单、风险检查 | Docker 本地环境 |
| 压测/恢复演练 | P95、连接池、重启、迁移、回滚 | 预生产 |

**生产上线底线：**

- 不使用 SQLite 作为运行库。
- 风控评估可回放事件、特征、规则、模型版本、案件与操作日志。
- 模型未达到指标或未通过影子期时，只能纯规则降级，不能伪装为模型可用。
- Docker/MySQL、迁移、权限、审计、日志、告警、回滚和 MySQL 集成测试全部通过后，才可称为生产级。
