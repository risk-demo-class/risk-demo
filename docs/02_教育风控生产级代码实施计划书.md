## 4. 数据库与 SQL 计划

### 4.1 业务表（按外键依赖顺序）

1. 基础维度：`student`、`course_category`、`course`、`enrollment_status`、`refund_status`、`verification_status`。
2. 账户与设备：`student_profile`、`device_binding`、可选 `access_channel`。
3. 核心交易：`enrollment`、`learning_progress`、`refund_request`、`credential_verification`。
4. 索引：`user_id + 时间`、`device_fingerprint_hash + 时间`、`enrollment_id`、`credential id_card_hash`、退款关联报名。

### 4.2 风控表（保留旧项目能力）

- `risk_rule`：规则版本、类别、优先级、启停、软删、条件 JSON、动作。
- `risk_blacklist`：类型、值、原因、失效时间、软删、创建时间。
- `risk_event`：标准化事件及请求快照。
- `risk_feature`：事件特征快照，含实体类型和实体 ID。
- `risk_assessment`：规则结果、规则分、模型分、最终分、模型版本、结论。
- `risk_case`：案件状态、类别、风险详情、审核人/意见/时间、来源业务 ID。
- `risk_user_profile`：最近风险画像，仅作运营汇总，不取代快照。
- `risk_alert`、`risk_action_log`：告警和不可抵赖操作审计。

### 4.3 SQL 文件与迁移规则

- `init_all.sql` 按业务表→风控表→基础数据→教育规则数据执行。
- 每次字段或索引变化必须新增命名迁移，不改历史初始化脚本来伪造升级。
- 每个迁移必须幂等、记录正向与回滚 SQL、在 MySQL 测试库验证。

## 5. 实施任务（必须按顺序）

### 任务 1：创建生产工程骨架

**范围：** 复制旧项目目录形态与 uv 环境配置；删除运行期 SQLite 依赖，不删除旧项目。

**验收：**
- `uv venv`、`uv sync` 或锁定依赖可重复创建环境。
- 教育项目可独立 import，所有 router 已注册但不混入旧项目模块。
- 目录与旧项目的层次对应关系写入 `docs/source_mapping.md`。

### 任务 2：Docker、MySQL、环境配置与启动前自检

**范围：** 复制并业务化 `docker/`、`.env.example`、`run_app.py`、`database.py`、`config.py`。

**验收：**
- `docker compose up -d` 启动 MySQL、App、Nginx。
- MySQL 健康检查成功后 App 才启动。
- 启动前检查环境文件、依赖、MySQL、初始化状态、端口、模型状态。
- 密钥不写入 Git；生产密码没有默认弱值。

### 任务 3：教育业务 DDL、风控 DDL与迁移测试

**范围：** 完成全部教育表、外键、索引、枚举/状态和迁移脚本。

**验收：**
- 新库能从零初始化；旧测试库可执行增量迁移。
- 外键、唯一约束、软删过滤、关键索引均由集成测试验证。
- 不存在 SQLite `.db` 作为运行数据源。

### 任务 4：教育模型、Schema 与种子数据

**范围：** `models_business.py`、`models_risk.py`、`schemas.py`、教育业务/规则初始化数据。

**验收：**
- 报名、退款、认证、设备、黑名单可通过真实 MySQL 关联查询。
- 所有 Pydantic 入参限制事件类型、长度、分页范围和状态流转值。
- 演示数据覆盖正常、人工审核、拒绝三个结论。

### 检查点 A：基础设施

- Docker 三服务健康；MySQL 测试库 DDL 集成测试通过；无 SQLite 运行配置。

### 任务 5：教育四步事件服务

**范围：** 重建 `service/validator.py` 与 `service/event.py`。

**验收：**
- 三事件均验证来源存在、用户归属和关联业务完整性。
- 报名补全课程/设备上下文；退款补全报名/学习上下文；认证补全证件/设备上下文。
- 黑名单按学员、证件/学号哈希、设备哈希短路，并记录保护动作/审计策略。

### 任务 6：教育七步决策引擎与特征仓

**范围：** 按旧 `engine/decision.py` 的七步结构重写 `feature.py`、`rule.py`、`decision.py`。

**验收：**
- 每次非短路事件至少写入事件、特征、评估；高风险写案件。
- 报名、退款、认证采用显式处理器映射，避免业务条件散落在共享函数。
- 特征命名、实体类型、特征列清单、训练脚本保持单一事实来源。

### 任务 7：教育规则、版本与黑名单运营

**范围：** `rule.py`、`blacklist.py`、对应 service/templates/tests。

**验收：**
- 规则创建、编辑、启停、软删、优先级、版本发布和回滚均审计。
- 黑名单可失效、软删、去重；拒绝加黑与案件审核同事务。
- 规则条件 JSON 被白名单校验，非法运算符/字段不得执行。

### 任务 8：案件、评估、画像与审计闭环

**范围：** `case.py`、`assessment.py`、`profile.py`、`action_log.py`。

**验收：**
- 状态机、审核人、意见、时间、自动拒绝、超时关闭、案件去重完整实现。
- 案件详情能回放事件、特征、规则、模型版本、评估和操作历史。
- 列表全部分页，详情查询避免 N+1。

### 检查点 B：三场景实时闭环

- MySQL 集成测试覆盖正常报名、共享设备、低学习退款、连续认证失败、黑名单拒绝、案件审核。

### 任务 9：模型训练、评估与发布

**范围：** 对齐旧项目 `ml_model.py`、训练/造数脚本、模型元数据和配置。

**验收：**
- 训练集与线上特征列严格一致，训练/验证按时间切分并防数据泄漏。
- 产出 AUC、PR-AUC、F1、Precision、Recall、混淆矩阵、特征重要性、分场景指标。
- 模型文件附带版本、特征版本、数据时间窗、标签定义和指标；支持未加载时纯规则降级。
- 模型先影子运行，达到业务门槛后再配置融合权重。

### 任务 10：仪表盘、告警、调度与运营页面

**范围：** 保留旧 `dashboard.py`、`alert.py`、`scheduler.py` 与页面结构。

**验收：**
- 指标来自 MySQL 聚合，不把全量评估拉到 Python 内存。
- 展示事件量、拒绝/审核率、案件积压、规则命中、模型分布、告警状态。
- 定时器可启动/停止，任务幂等，失败写日志和告警。

### 任务 11：权限、安全、可观测性与前端验收

**范围：** 认证/授权、脱敏、日志、健康检查、页面操作校验。

**验收：**
- 运营角色与模型角色分权；普通学员不能访问后台接口。
- 日志不输出敏感值；前端所有动态文本安全渲染。
- `/health`、结构化日志、错误追踪指标和 Docker 日志可用。
- 真实浏览器验证控制台无错误、关键 API 网络请求正常、页面可用。

### 任务 12：发布演练与回滚

**范围：** CI、Docker 部署手册、备份/恢复、迁移回滚、模型回滚。

**验收：**
- 在空环境完成一键部署、初始化、种子数据、训练影子模型、冒烟测试。
- 可回滚 SQL 迁移、规则版本、模型版本和应用镜像。
- 压测结果与容量假设写入发布记录。

## 6. 测试策略

| 层级 | 目标 | 运行环境 |
|---|---|---|
| 单元测试 | 规则条件、评分融合、状态机、特征纯函数 | 无数据库 |
| MySQL 集成测试 | 外键、事务、迁移、Router/Service/Engine 链路 | 独立 `education_risk_test` 库 |
| 契约测试 | API Schema、错误码、分页、权限 | FastAPI + MySQL 测试库 |
| 浏览器测试 | 仪表盘、规则、案件、黑名单、风险检查 | Docker 本地环境 |
| 压测/恢复演练 | P95、连接池、重启、迁移、回滚 | 预生产环境 |

## 7. 实施顺序与依赖

```text
基础设施(1-3)
  → 数据模型(4)
  → 事件/引擎(5-6)
  → 规则、案件、审计(7-8)
  → 模型训练(9)
  → 告警与前端(10-11)
  → 发布演练(12)
```

任务 1–4、5–8、9–11、12 各自是必须验收的停点。未经停点验收不得进入下一阶段；尤其不能在没有 MySQL 迁移和真实标签验证前宣称生产可用。

## 8. 当前项目处理建议

现有 `education_risk` SQLite 版本只可作为业务原型和规则草稿参考，**不应迁移为生产运行底座**。生产实现应新建独立目录/分支，按本计划从旧项目源码骨架复制，再逐层替换电商业务；保留原型供字段和规则对照，不直接在其上继续累积改动。
