# 教育行业 AI 风控生产级业务计划书

## 1. 项目定位与边界

本项目是职业技能在线教育平台的**交易与资质可信风控系统**。它保护报名收入、退款权益和证书/学历认证可信度；不评价学生成绩，不建设考试防作弊、直播打赏或内容审核系统。

生产目标是：每一笔受控教育事件都能完成实时判定、保留可复核证据、必要时进入人工案件、可被规则和模型共同解释，并支持审计、告警、模型迭代与回滚。

## 2. 业务角色

| 角色 | 业务动作 | 可见数据 | 权限边界 |
|---|---|---|---|
| 学员/付款人 | 报名、学习、退费、提交认证 | 本人业务结果 | 不可见风控特征、规则、他人信息 |
| 教师/课程运营 | 维护课程与学习交付 | 课程、学习进度汇总 | 不可审核风险案件 |
| 风控运营 | 查看评估、处理案件、维护规则与黑名单 | 脱敏业务信息、证据、审计轨迹 | 不可直接篡改原始事件/特征/评估 |
| 风控管理员 | 发布规则版本、处理高权限黑名单、处置告警 | 全部风控数据 | 规则发布、回滚、权限审批需审计 |
| 数据/模型人员 | 离线训练、评估、发布模型 | 脱敏训练集、指标 | 不直接操作线上案件结论 |
| 系统任务 | 超时关案、告警、模型加载 | 受限系统权限 | 所有动作记录为 `system` 审计 |

## 3. 三条核心业务链路

### 3.1 课程报名风险

**触发点：** 创建报名并进入支付确认或支付成功状态。

**主要风险：** 同设备批量新账号、薅新客优惠、异常高额/高频报名、黑名单主体再次报名。

**输入证据：** 学员、课程、报名单、优惠、支付结果、设备指纹哈希、IP/渠道（可在第二阶段接入）。

**关键规则：**

| 编号 | 信号 | 建议动作 |
|---|---|---|
| EDU-ENR-001 | 7 日同设备关联新学员数达到阈值 | 人工审核或拒绝 |
| EDU-ENR-002 | 新账号短时多次报名/累计金额超阈值 | 人工审核 |
| EDU-ENR-003 | 同课程短时集中新账号报名 | 标记/人工审核 |
| EDU-ENR-004 | 学员、证件哈希或设备哈希命中黑名单 | 拒绝（一票否决） |

### 3.2 退费申请风险

**触发点：** 学员提交退款申请。

**主要风险：** 极低学习投入后频繁退款、占用课程资源套利、同账户持续高额退款。

**输入证据：** 原报名单、退款单、退款前学习分钟数、完成率、近 90 天退款次数/金额、退款原因。

**关键规则：**

| 编号 | 信号 | 建议动作 |
|---|---|---|
| EDU-REF-001 | 学习不足 5 分钟即退款 | 人工审核，不自动拒绝 |
| EDU-REF-002 | 90 天退款次数达到阈值 | 标记/人工审核 |
| EDU-REF-003 | 90 天退款金额达到阈值且完成率异常低 | 人工审核 |
| EDU-REF-004 | 黑名单主体请求退款 | 拒绝或冻结，按平台退款政策处理 |

### 3.3 学历/身份认证风险

**触发点：** 提交学历、身份或报名资格认证。

**主要风险：** 伪造材料、多次失败试探、黑名单主体获取课程权益或证书资格。

**输入证据：** 认证类型、证件/学号哈希、认证结果、失败原因码、提交时间、关联设备。

**关键规则：**

| 编号 | 信号 | 建议动作 |
|---|---|---|
| EDU-VER-001 | 30 天连续认证失败达到阈值 | 人工审核 |
| EDU-VER-002 | 证件/学号哈希命中黑名单 | 拒绝（一票否决） |
| EDU-VER-003 | 多账号复用同一证件哈希或设备 | 人工审核/拒绝 |

## 4. 统一风险决策

每一个事件必须经过同一条链路：

```text
事件接入 → 业务归属校验 → 上下文补全 → 黑名单短路
        → 特征计算 → 特征快照 → 规则匹配 → 模型预测
        → 决策融合 → 事件/评估/案件/画像/审计落库
```

决策等级统一为：`通过`、`标记`、`人工审核`、`拒绝`。其中黑名单和确认型高危规则可一票否决，模型不得把一票否决降级为放行。

**不可变原则：** 原始事件、特征快照、规则命中和评估结果只能新增，不能由人工审核覆盖；审核改变的是案件状态并产生操作审计。

## 5. 数据对象与隐私约束

| 数据域 | 生产对象 | 关键字段/约束 |
|---|---|---|
| 学员 | `student` | `user_id`、角色、实名状态、学号哈希；姓名仅保存脱敏值 |
| 课程 | `course` | 课程、类目、价格、课时、教师 |
| 报名 | `enrollment` | 报名单、学员、课程、实付/优惠、支付/报名状态、时间 |
| 学习 | `learning_progress` | 总学习分钟、完成率、最后活跃时间 |
| 退费 | `refund_request` | 原报名、金额、原因码、退款前学习数据、状态 |
| 认证 | `credential_verification` | 类型、证件哈希、状态、失败原因码、提交时间 |
| 设备 | `device_binding` | 设备指纹哈希、学员、首次/最后活跃时间 |
| 风控 | `risk_event`、`risk_feature`、`risk_assessment`、`risk_case` | 事件与评估可回放；高频查询字段必须建索引 |

不得存储明文身份证号、明文设备指纹、支付卡信息；黑名单只保存业务必要的哈希/脱敏标识。训练集使用脱敏快照，禁止直接把原始个人信息输入模型。

## 6. 人工案件与运营闭环

案件状态机：

```text
待审核 → 审核中 → 已通过 / 已拒绝 / 已关闭
待审核 → 已通过 / 已拒绝 / 已关闭
终态不可再改
```

人工审核必须记录审核人、审核意见、审核时间、所依据的规则/特征证据；拒绝并加入黑名单应在同一事务内完成。超时案件由系统任务关闭或升级告警，不能静默遗失。

## 7. 模型策略与生产门槛

模型是规则的补充，不是替代。

1. 训练样本以已结案案件、确认欺诈、有效申诉结果为标签来源，不能简单用“规则命中”当唯一真值标签。
2. 特征版本与模型版本必须绑定；改特征、规则融合权重或标签策略必须重新训练并留档。
3. 离线验证至少输出 AUC、PR-AUC、F1、召回率、精确率、混淆矩阵和按报名/退款/认证场景的分桶指标。
4. 发布采用影子评分或灰度：先记录模型建议，不影响决策；通过稳定期后再进入融合权重。
5. 需要漂移监控：特征分布、拒绝率、人工审核率、规则命中率、模型分数分布、审核后坏账率。

## 8. 生产验收指标

| 维度 | 初始上线目标 |
|---|---|
| 可用性 | 健康检查通过；服务与 MySQL 可恢复；关键 API 有超时与错误日志 |
| 审计 | 100% 风险评估可回查事件、特征、规则、模型版本与案件操作 |
| 性能 | 风险检查 P95 目标由压测确定；不允许 N+1 查询和无分页后台列表 |
| 准确性 | 模型离线指标及人工复核坏账率达到业务设定门槛后才参与决策 |
| 安全 | 权限隔离、脱敏、密钥仅来自环境变量、SQL 参数化、操作审计 |
| 运维 | Docker Compose 可启动 MySQL/App/Nginx；迁移可重复执行并可回滚 |

## 9. 不在本期范围

- 考试防作弊、直播互动、内容审核
- 对接真实支付渠道或向学生自动扣款
- 将模型分数直接视为最终业务事实
- 在没有真实标签与审批流程前宣称模型“训练优秀”
