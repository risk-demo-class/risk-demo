# 业务表设计（场景 F：医疗风控）

8 张业务表：每张列出核心字段与用途，并标注与电商版的对应关系。

| 表名 | 核心字段 | 用途 | 与电商版对应 |
|---|---|---|---|
| `UserInfo` | user_id, name, id_card_hash, medical_card_no, insurance_type, register_at | 参保人档案：医保卡号 / 参保类型是新风控维度 | ≈ 用户表（新增医保卡 / 参保类型） |
| `Hospital` | hospital_id, name, level, province, city, is_insured | 医院档案：级别 / 地区 / 是否定点 | 新增（电商没有"医院"概念） |
| `Doctor` | doctor_id, name, hospital_id, department, title, license_no | 医生档案：内部人风控维度 | 新增（电商没有"医生"） |
| `Appointment` | appt_id, user_id, hospital_id, department, doctor_id, appt_time, pay_amount | 挂号记录：电商"订单"变"挂号" | ≈ 订单表 |
| `Prescription` | rx_id, doctor_id, user_id, hospital_id, items, total_amount, is_insured | 处方单：开方与用药合规的核心载体 | 新增（电商没有"处方"） |
| `InsuranceClaim` | claim_id, user_id, hospital_id, total_amount, insured_amount, claim_status, submit_at | 医保结算单：基金支出的强监管环节 | ≈ 支付表（语义完全不同） |
| `DrugOrder` | drug_order_id, rx_id, user_id, drug_name, quantity, drug_category, is_otc | 药品订单：处方流转后的"商品"环节 | ≈ 订单明细（商品） |
| `BlacklistExtra` | entry_id, type, value, reason, expire_at | 扩展黑名单：type 增加医保卡 / 身份证 / 执业证 / 医院编码 | ≈ 黑名单表（类型扩展） |

设计要点：

- 风控核心 9 张表（risk_rule / risk_event / risk_feature / risk_assessment / risk_case / risk_blacklist / risk_user_profile / risk_action_log / risk_alert）完全复用，本表只做业务侧数据。
- 事件类型对应：医保结算（insurance_claim）、处方审核（prescription）、挂号（appointment）、药品代购（drug_order）。
- 特征计算三大族对应：compute_user_features ← UserInfo；compute_order_features ← Appointment / InsuranceClaim / DrugOrder；compute_address_features ← Hospital（参保地 vs 就医地）。
