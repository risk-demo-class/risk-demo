# Agent 设计说明 (Vibe Coding 复盘)

## 一、协作方式

本项目的制造业风控系统是在参考电商版 `AI_Risk` 项目基础上, 通过 LLM (GPT) 协作完成的行业迁移, 遵循任务书"复用内核、重写业务层"的边界:

| 阶段 | LLM 承担的工作 | 人工/参考项目承担的工作 |
|---|---|---|
| 业务理解 | 输出制造业业务说明 (欺诈场景/字段/事件/术语) | 确认行业范围 (场景 D) |
| 数据层 | 设计 7 张业务表 schema + DDL + 造数脚本 | 复用 init_db 一键流程 |
| Pipeline | 重写 25 维特征工程 + 8 条规则 + 事件分支 | 复用 7 步决策流水线 |
| 训练 | 调通 XGBoost 训练链路 (val_auc 0.99) | 复用 ml_model 双轨融合 |
| 演示 | 适配前端文案 + 冒烟验证脚本 | 复用全部页面框架 |

## 二、关键设计决策 (LLM 与工程师的判断)

1. **风控主体 = 经销商**: 把电商的 user_id 概念映射为经销商账号, `user_id == dealer_id`, 特征/规则/画像全部围绕经销商, 最大程度复用核心表结构。
2. **"地址"特征族 → "区域"特征族**: 制造业没有收货地址, 用 `addr_ship_region_count / addr_dealer_region_count / addr_ship_is_new` 表达发货区域行为, 保持 25 维特征数量与实体分类不变。
3. **事件类型收敛为 3 个**: 经销商订货 / 设备保修 / 跨区串货举报, 对应任务书 8 条核心规则, 避免规则与事件错配。
4. **黑名单类型按行业扩展**: 在保留 用户/手机号/地址 基础上增加 经销商/设备SN/维修工, 拦截优先级 用户 > 经销商 > 设备SN > 维修工。
5. **规则可解释性优先**: 8 条核心规则直接用特征阈值表达 (如 `order_quantity > 100`), 与 XGBoost 双轨融合, 兼顾可解释与效果。

## 三、踩坑与修正 (对后续学员的提示)

- **编码问题**: Windows 终端 GBK vs 项目 UTF-8, 脚本一律 `sys.stdout.reconfigure(encoding="utf-8")`。
- **缓存坑**: 复制项目时嵌套 `__pycache__` 里的旧字节码会串路径 (pytest 报错路径指向旧盘符), 必须清理缓存。
- **核心表不动**: 只改枚举取值不改表结构, 保证 9 张风控表 schema 与电商版一致, 决策流水线零改动。
- **特征对齐**: `FEATURE_COLUMNS` 与 `feature.py` 25 个 key 必须一一对应, 否则 XGBoost 训练/推理退化为 0 填充。

## 四、Prompt 模板 (可复用)

> 我要做一个制造业 (经销商渠道) 风控系统, 业务层跟电商完全不同。请基于现有电商版 AI_Risk 项目:
> 1) 复用 9 张风控表 + 7 步决策流水线;
> 2) 重写业务表 (经销商订货/设备保修/跨区串货举报)、25 维特征、8 条规则;
> 3) 产出造数脚本并跑通 init_db → gen_data → train_xgb → web 演示 全链路。
