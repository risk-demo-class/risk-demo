# PingPong 跨境收款字段映射与规则说明

## 1. 业务边界

本系统不把跨境收款当成电商订单欺诈。核心对象是商户主体、平台店铺、虚拟收款账户、境外付款人、贸易背景、入账审核、换汇、账本和出款路径。实时入账评估的主链路为：

```text
入账通知 -> 黑名单预检 -> 主体与贸易材料校验 -> point-in-time 特征 -> MySQL 规则 -> XGBoost
         -> 联合决策 -> risk_event -> risk_decision -> 人审案件/放行/拒绝
```

资料依据：PingPong 开放平台把跨境收款区分为平台收款和外贸收款，并通过虚拟账户、暂存余额和入账通知组织流程；出款审核包含通过、退回和拒绝等状态。业务设计同时参考 FATF 贸易型洗钱指标、FinCEN BEC 风险和 FCA 钱驴账户监测框架。

## 2. 从电商风控到跨境收款的映射

| 原电商概念 | 跨境收款对应概念 | 风控关注点 |
| --- | --- | --- |
| 消费者 | 跨境卖家/外贸企业 `customers` | KYB、UBO、申报规模和实际业务一致性 |
| 商品 | 贸易背景与单据 `trade_orders`, `trade_documents` | 合同、发票、报关单、物流单真实性 |
| 订单 | 贸易订单和入账分配 | 入账金额是否有足额贸易支撑 |
| 收货地址 | 付款人、买方、开户国和支付走廊 | 地理关系、高风险走廊、第三方代付 |
| 支付账户 | 境外付款人 `counterparties` | 首次付款、跨商户付款、钱驴标签 |
| 收款账户 | 虚拟账户 `virtual_accounts` | 账户用途、币种、店铺绑定和状态 |
| 退款 | 原路退汇/退款 | 是否回到原付款路径，防止资金转移 |
| 发货 | 入账后换汇与出款 | 资金快进快出、接近清空余额 |
| 用户设备 | 商户操作设备与授权凭据 | 多商户共设备、凭据复用、账号接管 |

### 主要关联

- `partner -> customer -> inbound_payment/payout/risk_event`：支持合作方级快速分区与特征汇总。
- `customer -> virtual_account -> inbound_payment`：检查账户用途、币种和店铺绑定。
- `counterparty -> inbound_payment -> trade_order`：比对实际付款人与合同买方。
- `trade_order -> trade_document/allocation`：将单据真实性与入账额度消耗放在同一观察时点。
- `inbound_payment -> fx_order/payout/ledger_entry`：追踪入账后资金去向。
- `risk_event -> risk_decision -> risk_case`：保留特征快照、决策依据和人审结论。
- `risk_blacklist -> inbound_payment/payout -> risk_event`：按稳定业务标识精确命中，同时记录命中次数和最近命中时间。

## 4. 事件类型

| 事件 | 触发时机 | 主体 | 主要处理 |
| --- | --- | --- | --- |
| `CUSTOMER_ONBOARDING` | 商户提交 KYB | customer/person/device | 主体、UBO、设备网络规则 |
| `PROFILE_CHANGED` | 业务类型、规模、人员变更 | customer/person | 重算主体基线 |
| `STORE_AUTH_CHANGED` | 店铺授权成功/失效 | store/customer | 凭据复用与接管检测 |
| `AUTH_ATTEMPTED` | 登录、MFA、重置密码 | customer/device | ATO 速度与异常地理位置 |
| `VA_ASSIGNED` | 虚拟账户分配/绑定 | virtual_account/customer/store | 用途、币种与店铺关系校验 |
| `INBOUND_RECEIVED` | 收到银行或渠道入账通知 | inbound/customer/counterparty | 实时特征、规则和模型评估 |
| `INBOUND_AUDIT_SUBMITTED` | 提交入账审核材料 | inbound/trade_order | 单据核验与额度分配 |
| `INBOUND_AUDIT_DECIDED` | 审核通过/退回/拒绝 | inbound/customer | 标签回流和暂存资金处置 |
| `FX_REQUESTED` | 商户发起换汇 | fx_order/customer | 入账后快速换汇与币对风险 |
| `PAYOUT_REQUESTED` | 提现/付款发起 | payout/customer/bank_account | 资金去向、新受益人、BEC/ATO |
| `PAYOUT_DECIDED` | 出款通过/退回/拒绝 | payout/customer | 计入决策结果与案件 |
| `inbound.risk.assessed.v1` | 风险工作台评估入账 | inbound/customer/counterparty | 保存特征、黑名单和规则/模型决策 |
| `payout.risk.assessed.v1` | 风险工作台评估出款 | payout/customer/bank_account | 保存出款特征、名单命中和决策链 |
| `REFUND_REQUESTED` | 退汇/退款 | inbound/counterparty | 强制校验原始付款路径 |
| `CASE_UPDATED` | 调查员处理案件 | case/customer/entity | 沉淀处置结论与标签 |

## 6. 典型欺诈和洗钱套路

1. 虚假贸易包装：重复使用合同、发票、报关单或物流单，伪造贸易背景承接不明资金。
2. 高报/低报价格：入账金额与合同、申报规模或同类交易严重偏离。
3. 第三方代付：实际付款人与合同买方无合理关系，利用商户 VA 做资金通道。
4. 钱驴网络：同一付款人给多商户汇款，或多商户共享设备、UBO、凭据和受益账户。
5. 空壳主体：新设公司缺少稳定业务画像，但快速产生超申报规模的跨境收付。
6. BEC 指令篡改：攻击者接管邮箱或账号，临时修改受益账户并发起大额出款。
7. 账号接管：异常设备/地区登录、MFA 失败或密码重置后，新增受益人并快速出款。
8. 快进快出：入账后立即换汇、拆分出款或接近清空余额，缩短可追溯窗口。
9. 制裁规避：使用中间付款人、高风险走廊、名称变体或多层受益人规避筛查。
10. 退款分流：以取消贸易为由，要求将退款打入与原付款人无关的第三方账户。

## 7. 决策与模型说明

- 规则分：`max(命中分) + 3 * 额外命中数`，上限 100；否决规则最低 90。
- 模型分：XGBoost 输出入账高风险概率，当前 41 维特征。
- 阈值：在独立 15% 校准集上选择 F1 阈值，然后一次性评估未触及的 15% 时间验证集。
- 当前合成数据：`val_auc = 0.773092`, `val_f1 = 0.533333`。
- 生产改造：必须引入真实案件结论、拒付/召回/制裁处置标签，并进行漂移监控、公平性审核、规则冲突分析和模型版本回滚。

## 8. 数据库同步与审计

```bash
export PINGPONG_DB_PASSWORD="$(docker exec mysql-db printenv MYSQL_ROOT_PASSWORD)"
.venv/bin/python scripts/sync_rules.py
.venv/bin/python scripts/sync_blacklist.py
```

`scripts/sync_rules.py` 按 `rule_id` 幂等更新规则；`scripts/sync_blacklist.py` 按“主体类型 + 归一化标识”幂等更新合成名单。表不存在时会通过 SQLAlchemy metadata 创建。生产规则和黑名单变更应追加发布单、审批人、生效窗口和回滚版本。
