# P0 实施报告

## 结果

P0“项目骨架与医疗数据层”已完成，并在本地 MySQL 新库 `ai_risk_medical` 上完成真实验证。参考项目及其 `ecs` 数据库未被修改。

## 交付内容

- Python 3.11 + uv 项目，根目录以 `pyproject.toml` 和 `uv.lock` 为唯一依赖基线。
- Router → Service → Engine → Model 分层骨架及 FastAPI `/health` 端点。
- 9 张医疗语义的风控核心表。
- 8 张医疗业务表：患者、医生、医院、挂号、处方、处方明细、医保结算、患者设备。
- ORM 与 MySQL DDL 对齐；金额列同时使用数据库 `DECIMAL` 和 Python `Decimal`。
- 安全、幂等的数据库初始化脚本，只创建缺失数据库/表，不提供默认删除能力。
- 固定随机种子的合成数据脚本，默认生成 200 患者、20 医生、5 医院、500 挂号、500 处方、1000 明细和 500 结算。
- 4 类医疗事件与业务单据映射、存在性和患者归属校验。
- 模型、DDL、校验、造数、安全、健康端点和真实 MySQL 集成测试。

## 关键设计决策

- 所有身份证、医保卡、手机号和设备标识只保存 SHA-256 合成摘要。
- 本机数据库密码只存在于 Git 忽略的 `.env`；源码与 `.env.example` 无密码默认值。
- 批量造数按外键层级分段 `flush`，整个数据集最终以单事务提交，失败时回滚。
- 模型或数据库集成测试不具备显式条件时标记 skip，不伪造成功。
- 初始化脚本校验数据库名，只接受字母、数字和下划线，避免标识符注入。
