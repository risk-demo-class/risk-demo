# agent_design.md — 我怎么用 LLM 协作完成这个项目

> Vibe Coding 复盘：本项目业务层（表 / 特征 / 规则 / 数据 / 校验）全部由 LLM 协作产出，
> 人工负责行业判断、评审、阈值定夺与跑通验证。

## 1. 使用的 AI 工具与分工

| 任务 | 工具 | 产出 |
|---|---|---|
| 业务调研 | GPT / Claude | `1-业务说明.md`（欺诈场景 / 字段 / 事件类型 / 术语） |
| Schema + 造数 | GPT | `models_business.py` + `gen_business_data.py` |
| 特征 + 规则 | GPT | `feature.py` 25 维 + 11 条规则 JSON |
| 训练与调优 | GPT + 本机脚本 | `train_xgb_model.py` 评估指标 |
| 文档与讲解 | GPT | README / 录屏脚本 |

## 2. 人机协作流程

```text
LLM 产出 → 人工 review → 跑通验证 → 迭代
```

关键节点人工判断：

1. **行业选择**：选 A 旅游（深度包最全、展示效果好）。
2. **schema 评审**：7 张表字段是否覆盖规则所需特征（拒签次数、航班数、证件号…）。
3. **规则阈值**：5 万 / 3 国 / 7 天 / 30% 匹配率等阈值是否贴合行业常识。
4. **特征命名**：`user_/order_/pax_` 前缀决定 risk_feature 实体类型，必须与 `FEATURE_COLUMNS` 同步。
5. **验收**：init_db → 造数 → 风控检查 → 训练，全链路跑通才算完成。

## 3. 提示词模板（4 个任务）

### 任务 1：业务说明

```text
我要做一个【旅游行业】的风控系统，业务层跟电商完全不同。请调研典型欺诈场景、
关键业务字段、业务事件类型，输出 1 页纸业务说明，符合国内监管要求。
```

### 任务 2：Schema + 造数

```text
这是我的业务说明：<粘贴>。请设计 7 张业务表 schema（SQLAlchemy + DDL），
字段/索引要考虑风控特征计算便利，同时写 Python 造数脚本，至少 100 条，
内置高风险画像用户保证规则可命中。
```

### 任务 3：特征 + 规则 + 训练

```text
这是我的业务表：<粘贴 schema>。请设计 3 大特征族（用户/订单/乘客）共 25 维，
写 compute_*_features，设计 11 条业务规则，跑通 XGBoost 训练并用 val_auc/val_f1 评估。
```

### 任务 4：文档与讲解

```text
这是我的代码与截图：<粘贴>。请写完整 README 和 5-8 分钟现场讲解脚本。
```

## 4. 迭代记录

| 轮次 | 问题 | 处理 |
|---|---|---|
| 1 | 事件类型还是电商的“下单/售后” | 全链路替换为 预订/支付/签证申请/退改签（schema/DDL/validator/模板） |
| 2 | 特征名与 XGBoost 列不一致 | 统一到 `FEATURE_COLUMNS` 25 维 + 测试 `test_xgboost.py` 校验 |
| 3 | 规则不命中样例数据 | 造数脚本内置 7 个 RISK 用户，逐个场景造数据 |
| 4 | 黑名单类型只有用户/地址/手机号 | 改为 护照号/身份证号/设备指纹/IP 等 7 种并按行业实现拦截 |

## 5. 总结

> 规则保底，AI 加分；分层解耦，可降可升。
> 人的价值：定行业、定边界、定阈值、跑通验收 —— 代码细节交给 LLM。
