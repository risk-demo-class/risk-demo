# 银行风险运营工作台前端实现与验收

> 实现日期：2026-08-12。技术栈保持 FastAPI + Jinja2 + Bootstrap 5 + 原生 JavaScript，没有引入前端框架或构建链。

## 1. 页面地图

桌面侧栏按风险运营流程排序：

1. `/` 运营总览：今日评估、高风险、待审案件、通过率、近 7 日趋势、规则 TOP 5。
2. `/risk-check` 风险检查：登录、转账、贷款申请、绑卡四事件；只提交 `event_type/source_id/user_id/event_data`。
3. `/rules` 规则管理：银行规则分类、四事件和通用规则、25 项特征条件构建器、启停与分页。
4. `/blacklist` 黑名单：用户、设备指纹、IP、银行卡号、身份证号五类实体；列表值自动脱敏。
5. `/cases` 风险案件：待办统计、人工复核、来源事件重做检查和银行画像。
6. `/assessments` 评估流水：四事件、等级、决策和用户筛选，展示规则与模型分。

`/chat` 保留为辅助分析入口，不占用六个核心运营位置，也不宣称不存在的模型监控能力。

## 2. 设计 token 与组件

共享样式集中在 `static/app.css`。核心 token 为深蓝 `#0B1F3A`、操作蓝 `#18518A`、画布 `#F4F7FB`、白色表面和蓝灰分隔线；绿、黄、橙、红只承载风险状态。卡片统一 10px 圆角和轻阴影，表单控件及导航触控目标不小于 44px，键盘焦点使用可见外框。

共用组件包括固定侧栏/移动抽屉、页面标题、指标卡、内容面板、风险徽标、结果反馈、特征网格、表格容器和粘底分页。没有装饰性渐变、真实银行 Logo 或未绑定 API 的假指标。

## 3. 状态与 API 绑定

- 总览绑定 `GET /api/dashboard/overview`，提供加载、无规则命中和可重试错误态；趋势图带隐藏文本摘要。
- 风险检查绑定 `POST /api/risk/check`，按钮在请求期间禁用。正常结果展示最终决策、0–100 分、规则表、模型概率与 sigmoid 分、25 项特征；黑名单短路明确显示 `blocked_by`、0 条规则、无特征且未调用模型。
- 规则、黑名单、案件和评估列表继续绑定原有 CRUD/分页 API；只改银行事件、类别和字段标签。
- 黑名单接口仍返回原始教学值，前端在插入 DOM 前按类型执行 `maskValue`；演示数据也只使用虚构标识或不可逆摘要。
- 风险检查对 API 文本使用 HTML 转义，用户补充上下文只接受 JSON 对象，且明确不能覆盖数据库中的可信金额、卡片、设备或 IP。

## 4. 响应式与可访问性

桌面目标为 1440×900：248px 固定侧栏，内容区自动避让；宽表在独立容器横向滚动，分页保持可见。移动目标为 390×844：顶部 64px 工具栏、抽屉导航、遮罩点击关闭和 Escape 关闭，关闭后焦点返回菜单按钮；内容改为单列，结果特征逐项纵向显示，表格保留可操作的横向滚动。

页面提供“跳到主要内容”、语义化 `main/nav/header`、表单 `label`、`aria-live` 结果区和至少 44px 的常用交互目标。风险状态均有文字，不仅靠颜色表达。

## 5. 与 Goal 1 简报的差异

- 总览没有增加黑名单拦截数、事件分布或告警区，因为现有 `/api/dashboard/overview` 不返回这些字段，添加占位会违反“不伪造接口数据”。保留现有四个真实指标和规则 TOP 5。
- 没有新增模型指标页；模型指标已作为版本化评估文档交付，避免为只读 JSON 引入新后端路由。
- 移动端列表采用可横向滚动表格，没有全面改成卡片行。原因是现有规则编辑、案件操作和评估详情均依赖表格列关系；本目标以不破坏行为和清晰滚动为优先，后续可在 Goal 4 进一步增强卡片视图。
- 实现 token 的部分色值在简报建议值附近做了轻微统一，例如操作蓝使用 `#18518A`；品牌方向、状态语义和对比原则不变。
