# 银行风控业务说明

> 范围：信用卡、贷款、转账、登录；对应任务书“任务 1：业务理解”。本文用于课堂演示和后续重构输入，不构成法律意见、授信意见或生产风控决策。

## 1. 业务边界与监管基线

| 业务域 | 本项目关注的动作         | 主要风险                  |
| --- | ---------------- | --------------------- |
| 信用卡 | 绑卡、卡片关联、异常使用     | 黑卡、盗刷、套现、卡片与用户关系异常    |
| 贷款  | 申请、收入与负债信息核验     | 多头借贷、资料矛盾、偿付能力不足      |
| 转账  | 发起转账、收付款关系与速度监测  | 账户接管、异地大额、多卡归集、资金快进快出 |
| 登录  | 身份、设备、IP 与地理环境校验 | 新设备、代理/Tor、撞库、异常地点登录  |

金融机构依法承担客户尽职调查、客户身份资料及交易记录保存、大额交易和可疑交易报告等反洗钱义务，系统应支持风险相适应的持续监测与审计留痕，而不能把单一阈值直接等同于违法结论（[《中华人民共和国反洗钱法》](https://www.npc.gov.cn/npc/c2/c30834/202411/t20241108_440887.html)，访问日期：2026-08-11；[《金融机构客户尽职调查和客户身份资料及交易记录保存管理办法》](https://www.pbc.gov.cn/zhengwugongkai/attachDir/2025/12/2025122909264498909.pdf)，自 2026-01-01 施行，访问日期：2026-08-11）。中国人民银行现行规则还要求对交易监测筛出的交易进行人工分析、记录排除或确认理由，并使可疑交易判断与客户尽职调查相互验证（[中国人民银行令〔2025〕第 10 号](https://www.pbc.gov.cn/tiaofasi/144941/144957/5863650/index.html)，访问日期：2026-08-11）。

## 2. 八类典型风险场景

| 编号 | 场景 | 可观察信号 | 演示处置 |
|---|---|---|---|
| F01 | 账户接管与异地大额转账 | 新设备或非常用城市登录后短时大额转账 | 拒绝或人工审核 |
| F02 | 多卡归集与资金快进快出 | 多张卡在短时间向同一卡集中转入，到账后快速转出 | 拒绝并形成案件 |
| F03 | 黑卡或涉诈账户关联 | 收款卡、设备、证件哈希命中黑名单 | 前置拦截 |
| F04 | 代理/Tor 隐匿位置 | 登录 IP 命中代理或 Tor，且与历史地理环境明显不一致 | 标记或人工审核 |
| F05 | 新设备大额操作 | 设备首次出现不足 7 天即发生高额转账或绑卡 | 人工审核 |
| F06 | 设备多人共用与批量养号 | 同一设备指纹短期关联多个 `user_id` | 标记并调查关联网络 |
| F07 | 多头借贷与债务压力 | 短期多次贷款申请、较高 `debt_ratio`、收入与申请额不匹配 | 人工审核 |
| F08 | 信用卡盗刷或套现特征 | 异常时段/地点高频交易、整数金额、卡片关系异常 | 拒绝或人工审核 |

《反电信网络诈骗法》要求银行业金融机构建立涉诈异常账户和可疑交易监测机制，并强调对交易、贷款等个人信息的保护；因此 F01–F06 是风险线索而非自动定罪标签（[中国人大网全文](https://www.npc.gov.cn/c2/c30834/202209/t20220902_319186.html)，访问日期：2026-08-11）。

## 3. 事件契约与关键字段

外部风险检查请求固定为 `event_type/source_id/user_id/event_data` 四字段；`order_id/receive_id` 只作为基线内部兼容字段，不新增为银行 API 必填项。

| `event_type` | `source_id` 指向 | 关键字段（节选） |
|---|---|---|
| `登录` | `LoginLog.login_id` | `user_id`、`device_id`、`ip_hash`、`geo_code`、`success`、`login_at` |
| `转账` | `Transaction.txn_id` | `from_card_hash`、`to_card_hash`、`amount`、`channel`、`device_id`、`ip_hash`、`geo_code` |
| `贷款申请` | `LoanApplication.loan_id` | `amount`、`term_months`、`purpose`、`monthly_income_band`、`debt_ratio`、`apply_at` |
| `绑卡` | `BankCard.card_id` | `card_no_hash`、`card_type`、`bank_code`、`bind_device_id`、`bind_at` |

以上已覆盖超过 10 个关键业务字段。后续业务表设计还需保留 `kyc_level`、`credit_score_band`、`is_proxy`、`is_tor`、`first_seen` 等可解释字段，但只使用虚构、枚举、掩码或哈希值。

## 4. 行业术语

| 术语 | 本项目含义 |
|---|---|
| KYC / 客户尽职调查 | 识别客户身份、业务关系与风险状况，并按风险持续复核 |
| AML | 反洗钱；包含内控、尽职调查、记录保存和大额/可疑交易报告等义务 |
| 设备指纹 | 对终端环境生成的不可逆标识，用于识别新设备和关联网络 |
| 黑卡 | 本演示中指已被内部风险名单标记的卡号哈希，不代表司法定性 |
| 多卡归集 | 多个付款账户在短时间向同一收款账户集中资金 |
| 多头借贷 | 短期向多个渠道或机构发起贷款申请所体现的信用风险信号 |
| 速度规则（velocity rule） | 在固定时间窗内统计次数、金额或关联主体数量的规则 |

## 5. 数据与使用边界

个人信息处理应遵循合法、正当、必要、诚信以及最小范围原则（[《中华人民共和国个人信息保护法》](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)，访问日期：2026-08-11）。银行保险机构还应建立覆盖数据全生命周期的安全治理、分类分级、访问控制、匿名化、监测和日志审计机制（[《银行保险机构数据安全管理办法》](https://www.nfra.gov.cn/cn/view/pages/governmentDetail.html?docId=1192311&generaltype=1&itemId=861)，访问日期：2026-08-11）。

- 仓库、截图和演示库不得出现真实身份证号、银行卡号、IP、手机号、密钥或客户资料。
- 标识符使用虚构值；卡号、证件、IP 等只保留掩码、哈希或粗粒度区域码，并限制访问与导出。
- 风险分和规则命中仅用于教学演示；阈值未经真实数据校准，不得直接用于授信、冻结账户、可疑交易报告或客户权益处置。
- 生产应用必须另行完成合法性基础、数据影响评估、模型验证、偏差监测、人工复核、申诉与审计机制。
