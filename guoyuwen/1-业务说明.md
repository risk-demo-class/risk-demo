# 银行风控业务调研说明

本说明围绕信用卡、贷款、转账和登录四类银行业务，梳理典型欺诈场景、关键业务字段、风险触发事件及常用行业术语，为后续业务建模和风控系统重构提供依据。

## 一、典型欺诈场景

| 编号 | 典型场景 | 主要业务表现 | 对应业务域 |
|---|---|---|---|
| F01 | 账户接管 | 新设备或非常用地点登录后，短时间内发起敏感操作 | 登录、转账 |
| F02 | 异地大额转账 | 登录地点与常用地点不一致，同时发生大额转账 | 登录、转账 |
| F03 | 多卡归集与快进快出 | 多张卡短时向同一卡集中转入，到账后迅速转出 | 转账 |
| F04 | 黑卡或涉诈账户关联 | 收款卡、绑卡卡片、设备或证件哈希命中内部风险名单 | 转账、绑卡 |
| F05 | 代理/Tor 隐匿位置 | 登录 IP 命中代理或 Tor，且与历史地理环境明显不一致 | 登录 |
| F06 | 新设备批量养号 | 同一设备关联多个用户，或首次出现后短时连续绑卡、转账 | 登录、绑卡 |
| F07 | 多头借贷 | 短期多次贷款申请，且负债率、收入与申请额不匹配 | 贷款 |
| F08 | 信用卡盗刷或套现 | 异常时段、异常地点、高频整数金额交易或卡片关系异常 | 信用卡、转账 |

这些场景是风险线索，不等同于违法或欺诈结论；高风险结果仍需结合客户尽职调查和人工复核。

## 二、关键业务字段

| 业务对象 | 关键字段 | 主要风控用途 |
|---|---|---|
| 客户 `UserInfo` | `user_id`、`kyc_level`、`credit_score_band`、`register_at` | 身份、信用与账户年龄 |
| 银行卡 `BankCard` | `card_id`、`card_no_hash`、`card_type`、`credit_limit_band` | 卡片关系、黑卡与额度风险 |
| 转账 `Transaction` | `txn_id`、`from_card_hash`、`to_card_hash`、`amount`、`channel`、`txn_at` | 金额、方向、渠道和速度规则 |
| 贷款申请 `LoanApplication` | `loan_id`、`amount`、`monthly_income_band`、`debt_ratio`、`term_months` | 多头借贷与偿付能力 |
| 登录日志 `LoginLog` | `login_id`、`success`、`device_id`、`ip_hash`、`geo_code`、`login_at` | 账户接管、异地和失败登录 |
| 设备指纹 `DeviceFingerprint` | `device_id`、`fingerprint_hash`、`first_seen`、`last_seen` | 新设备和多账号关联 |
| IP 环境 `IpGeoLocation` | `ip_hash`、`geo_code`、`is_proxy`、`is_tor` | 代理、Tor 与地理异常 |
| 扩展黑名单 `BlacklistExtra` | `blacklist_type`、`value_hash`、`reason`、`expire_at` | 卡、设备、IP 等风险名单 |

以上字段全部使用虚构、枚举、掩码或哈希值，不保存真实身份证号、银行卡号、IP 或手机号。

## 三、业务事件类型

业务事件表示“**什么时候触发风控**”，欺诈场景表示“**系统要识别什么问题**”。外部风险检查保持 `event_type/source_id/user_id/event_data` 四字段契约。

| `event_type` | `source_id` 指向 | 触发时机 | 对应的真实业务痛点 |
|---|---|---|---|
| `登录` | `LoginLog.login_id` | 用户发起登录或敏感身份校验 | 账户接管、新设备、异地登录、代理/Tor、撞库 |
| `转账` | `Transaction.txn_id` | 用户提交转账或支付类交易 | 盗转、异地大额、多卡归集、快进快出、黑卡收款 |
| `贷款申请` | `LoanApplication.loan_id` | 用户提交贷款申请 | 多头借贷、高负债、资料矛盾、偿付能力不足 |
| `绑卡` | `BankCard.card_id` | 用户绑定新的银行卡 | 盗绑卡、黑卡关联、卡户关系异常、异常设备批量绑卡 |

这 4 种事件分别覆盖身份、资金、信贷和卡片关系四条主要风险链路，属于银行风控的真实控制节点。信用卡异常使用可通过现有事件的 `event_data` 表达具体场景，不新增外部必填字段；`order_id/receive_id` 只保留为基线内部兼容字段。

## 四、行业术语表

| 术语 | 本项目中的含义 |
|---|---|
| KYC / 客户尽职调查 | 识别客户身份、业务关系与风险状况，并按风险持续复核 |
| AML | 反洗钱，包括内控、尽职调查、记录保存和大额/可疑交易报告等义务 |
| 设备指纹 | 对终端环境生成的不可逆标识，用于识别新设备和关联网络 |
| 黑卡 | 被内部风险名单标记的卡号哈希；不代表司法定性 |
| 多卡归集 | 多个付款账户在短时间内向同一收款账户集中资金 |
| 多头借贷 | 短期向多个渠道或机构发起贷款申请所体现的信用风险信号 |
| 速度规则（velocity rule） | 在固定时间窗内统计次数、金额或关联主体数量的规则 |

## 五、监管与数据边界

1. 金融机构应履行客户尽职调查、身份资料和交易记录保存、大额交易和可疑交易报告等义务；单一阈值不能直接等同于违法结论（[《中华人民共和国反洗钱法》](https://www.npc.gov.cn/npc/c2/c30834/202411/t20241108_440887.html)，访问日期：2026-08-11；[《金融机构客户尽职调查和客户身份资料及交易记录保存管理办法》](https://www.pbc.gov.cn/zhengwugongkai/attachDir/2025/12/2025122909264498909.pdf)，访问日期：2026-08-11）。
2. 对监测筛出的交易应进行人工分析，并记录排除或确认理由（[中国人民银行令〔2025〕第 10 号](https://www.pbc.gov.cn/tiaofasi/144941/144957/5863650/index.html)，访问日期：2026-08-11）。
3. 银行业需要建立涉诈异常账户和可疑交易监测机制，同时保护交易、贷款等个人信息（[《中华人民共和国反电信网络诈骗法》](https://www.npc.gov.cn/c2/c30834/202209/t20220902_319186.html)，访问日期：2026-08-11）。
4. 个人信息处理遵循合法、正当、必要、诚信和最小范围原则；演示数据只使用虚构、掩码或哈希值（[《中华人民共和国个人信息保护法》](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)，访问日期：2026-08-11）。
5. 银行数据应落实分类分级、访问控制、匿名化、风险监测和日志审计（[《银行保险机构数据安全管理办法》](https://www.nfra.gov.cn/cn/view/pages/governmentDetail.html?docId=1192311&generaltype=1&itemId=861)，访问日期：2026-08-11）。

> **适用性说明**：本项目仅用于教学演示。风险分、规则阈值和模型结果未经真实数据校准，不得直接用于授信、冻结账户、可疑交易报告或其他影响客户权益的生产决策。
