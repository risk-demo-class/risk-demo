# 教育行业风控业务说明

> 项目：教育行业 AI 风控系统  
> 基线：尚硅谷 AI_Risk 电商风控系统  
> 业务范围：在线课程报名、学习、退费和直播互动  
> 调研日期：2026-08-11

## 1. 项目背景与业务边界

本项目模拟一个面向学生、家长和老师的在线教育平台。用户可以购买课程、观看录播或直播、积累学习进度、申请退费，并在直播课堂进行互动消费。系统关注的不是“学生成绩好不好”，而是识别报名、退费、账号身份、设备关联和直播消费过程中的欺诈或滥用行为。

本项目只改造业务层，继续复用老师项目的通用风控能力：事件进入后依次进行业务校验、信息补全、黑名单检查和风险决策，最终输出风险分数、风险等级、决策和命中规则。核心请求仍为 `RiskCheckRequest(event_type, source_id, user_id, event_data)`。

演示系统以“在线教育平台”为一般场景；当课程面向 3—6 岁儿童和中小学生、属于校外培训业务时，还需要满足校外培训资金监管和未成年人保护要求。系统是教学项目，不替代正式法律、合规或监管系统。

## 2. 典型风险场景

| 编号 | 风险场景 | 典型行为 | 可观察信号 | 建议处置 |
|---|---|---|---|---|
| F01 | 批量新账号刷报名 | 同一设备控制多个新账号集中购买同一课程，制造虚假销量或套取渠道奖励 | 设备关联账号数高；账号注册不足 7 天；同课程短期报名密集 | 极高风险，拒绝或冻结后人工复核 |
| F02 | 0 学时或低学时异常退费 | 用户购买课程后几乎没有学习便申请大额退费，或反复利用活动和退费政策套利 | 学习时长低于 5 分钟；退费金额高；90 天内多次退费 | 高风险，进入人工审核 |
| F03 | 退费连环与优惠套利 | 多次使用优惠券或低价活动报名，领取权益后反复退费 | 90 天退费次数 ≥3；累计退费金额高；优惠金额占比高 | 中高风险，限制优惠并人工复核 |
| F04 | 大额集中报名 | 一个账号在短时间内购买多门高价课程，金额显著偏离历史水平 | 1 小时累计报名金额高；课程数多；新用户大额首单 | 高风险，人工审核并核验支付人 |
| F05 | 假学员或代理学习 | 同一设备关联多个互不相关的学员，可能存在代报名、代学习或账号工作室 | 单设备关联用户 ≥5；多个学号共用设备；登录地域异常切换 | 极高风险，拒绝或限制账号 |
| F06 | 学员身份不一致 | 用户角色、实名信息、学号或课程适用人群不匹配 | 老师账号购买仅限学生课程；实名状态异常；学号重复 | 中风险，标记并要求补充认证 |
| F07 | 未成年人直播异常消费 | 未成年人账号在直播课堂短时高额打赏，金额与年龄、历史消费不匹配 | 单场或单日金额高；短时连续支付；监护人同意状态缺失 | 高风险，拦截支付并转人工处理 |
| F08 | 黑名单身份或设备访问 | 已确认存在欺诈的用户、学号、证件哈希、设备或直播账号再次发起业务 | 关键标识命中有效黑名单 | 极高风险，直接拒绝并记录保护动作 |

项目最低验收选择 F01、F02、F05 作为必命中场景，同时保留正常学员样本，避免系统把所有请求都判为风险。

## 3. 关键业务对象

| 业务对象 | 作用 | 主要关系 |
|---|---|---|
| 用户 `UserInfo` | 保存学生、家长、老师账号及实名状态 | 一个用户可有多个订单、进度、退费和打赏记录 |
| 课程 `Course` | 保存课程分类、价格、老师和课时 | 一个课程可对应多个报名订单和学习进度 |
| 报名订单 `OrderInfo` | 表示用户购买一门课程 | 关联一个用户和一门课程 |
| 学习进度 `LearningProgress` | 记录累计学习分钟数和完成率 | 关联用户和课程，用于退费、代学判断 |
| 退费申请 `RefundRequest` | 保存退费原因、金额和申请时的学习情况 | 关联报名订单 |
| 直播打赏 `LiveReward` | 保存直播课堂消费和设备信息 | 关联用户和直播场次 |

## 4. 关键业务字段

| 字段 | 所属对象 | 含义 | 风控用途 | 数据保护要求 |
|---|---|---|---|---|
| `user_id` | 用户 | 平台用户唯一标识 | 聚合用户历史行为 | 使用内部编号 |
| `role` | 用户 | 学生、家长或老师 | 判断身份与课程是否匹配 | 普通业务字段 |
| `student_id` | 用户 | 学号或学员编号 | 重复身份和黑名单检查 | 展示时脱敏 |
| `id_card_hash` | 用户 | 身份证号不可逆哈希 | 同证多账号和黑名单检查 | 不保存明文身份证 |
| `real_name_status` | 用户 | 未认证、已认证、认证失败 | 身份风险判断 | 只保存状态 |
| `guardian_consent_status` | 用户 | 未成年人监护人同意状态 | 控制未成年人信息和消费 | 保留授权审计记录 |
| `register_at` | 用户 | 注册时间 | 计算账号年龄 | 普通业务字段 |
| `device_id` | 用户/事件 | 设备指纹编号 | 识别一机多账号 | 使用随机标识或哈希 |
| `course_id` | 课程 | 课程唯一标识 | 聚合同课程报名行为 | 普通业务字段 |
| `course_category` | 课程 | 课程类别 | 规则分组和客群比较 | 普通业务字段 |
| `course_price` | 课程 | 课程标准价格 | 识别异常折扣和大额报名 | 金额字段最小授权 |
| `target_role` | 课程 | 适用角色或学员类型 | 识别身份不匹配 | 普通业务字段 |
| `order_id` | 报名订单 | 报名单唯一标识 | 报名事件 `source_id` | 使用内部编号 |
| `total_amount` | 报名订单 | 实付金额 | 大额报名和累计金额特征 | 金额字段最小授权 |
| `discount_amount` | 报名订单 | 优惠金额 | 优惠套利判断 | 金额字段最小授权 |
| `order_time` | 报名订单 | 报名时间 | 1 小时聚合和夜间行为 | 控制保存期限 |
| `total_minutes` | 学习进度 | 累计学习分钟数 | 0 学时退费、异常代学 | 不推断无关敏感结论 |
| `completion_rate` | 学习进度 | 课程完成比例 | 判断履约进度和退费合理性 | 限业务用途使用 |
| `last_active_at` | 学习进度 | 最后学习时间 | 活跃度和异常登录判断 | 控制保存期限 |
| `refund_id` | 退费申请 | 退费单唯一标识 | 退费事件 `source_id` | 使用内部编号 |
| `refund_amount` | 退费申请 | 申请退回金额 | 退费比例与累计退费 | 金额字段最小授权 |
| `study_minutes_before_refund` | 退费申请 | 申请时已学分钟数快照 | 防止事后进度变化影响判断 | 作为审计快照保存 |
| `refund_reason` | 退费申请 | 用户选择的退费原因 | 规则分组和人工审核 | 避免收集无关隐私描述 |
| `reward_id` | 直播打赏 | 打赏记录唯一标识 | 打赏事件 `source_id` | 使用内部编号 |
| `reward_amount` | 直播打赏 | 单次打赏金额 | 未成年人和短时大额消费识别 | 金额字段最小授权 |
| `live_session_id` | 直播打赏 | 直播场次标识 | 计算单场累计金额 | 普通业务字段 |

以上共 26 个关键字段。数据库阶段会基于“后续特征能计算、敏感信息最小化”的原则确定最终字段和索引。

## 5. 业务事件类型

| 事件类型 | `source_id` 对应实体 | 触发时机 | 重点检查 |
|---|---|---|---|
| `课程报名` | `OrderInfo.order_id` | 报名订单提交或支付前 | 新账号、大额连报、同设备批量账号、身份与课程不符 |
| `退费申请` | `RefundRequest.refund_id` | 退费申请提交后、退款执行前 | 学习时长、退费次数、累计金额、优惠套利 |
| `直播打赏` | `LiveReward.reward_id` | 打赏支付执行前 | 年龄/监护同意、单次和单场金额、短时频率、黑名单 |
| `学习行为` | `LearningProgress.progress_id` | 学习进度更新或异常登录时 | 一机多账号、代学、异常地域或时段、进度突增 |

前 3 种满足任务书“事件类型至少 3 种”的要求；`学习行为` 用于展示教育行业区别于电商行业的业务特色。

## 6. 核心风控特征方向

| 特征族 | 教育行业解释 | 候选特征 |
|---|---|---|
| 用户特征 | 用户历史报名、学习、退费和消费画像 | 账号年龄、30 天报名数、90 天退费数、累计退费金额、课程数、累计打赏金额 |
| 业务单据特征 | 当前报名、退费或打赏单据的风险信号 | 当前金额、优惠比例、退费比例、退费前学时、是否夜间、1 小时累计金额 |
| 设备/身份关联特征 | 替代电商“地址特征”，识别账号关联和身份异常 | 设备关联用户数、同证件账号数、设备是否首次出现、角色是否匹配、是否实名、是否命中黑名单 |

所有模型输入最终转换为数值。身份证号、姓名等原始身份信息不直接进入模型；模型输出用于风险排序和决策辅助，涉及未成年人或高额资金的拒绝结论应保留人工复核和申诉渠道。

## 7. 初版业务规则

| 规则编号 | 规则名称 | 初版条件 | 风险等级 | 决策 |
|---|---|---|---|---|
| EDU_R001 | 刷单式报名 | 同一课程 7 天内被多个新账号集中报名，且关联同一设备 | 极高 | 拒绝 |
| EDU_R002 | 0 学时退费 | 学习时长小于 5 分钟并申请退款 | 高 | 人工审核 |
| EDU_R003 | 大额连报 | 1 小时内报名累计金额大于 30000 元 | 高 | 人工审核 |
| EDU_R004 | 假学员代理 | 同一设备关联不少于 5 个学员账号 | 极高 | 拒绝 |
| EDU_R005 | 退费连环 | 90 天内退款不少于 3 次且累计金额大于 10000 元 | 中 | 标记 |
| EDU_R006 | 直播消费异常 | 单场打赏大于 5000 元，且账号注册不足 30 天 | 高 | 人工审核 |
| EDU_R007 | 学员身份不符 | 用户角色或实名信息与课程适用对象不一致 | 中 | 标记 |
| EDU_R008 | 黑身份拦截 | 学号、证件哈希、设备指纹或直播账号命中黑名单 | 极高 | 拒绝 |

阈值是教学项目的初始值，后续需根据生成数据分布调整，使至少 3 条规则能稳定命中风险样本，同时避免正常样本大面积误报。

## 8. 行业术语表

| 术语 | 解释 |
|---|---|
| 课程报名 | 用户选定课程并生成报名订单的业务过程 |
| 课消 | 学员完成课程学习后，对已购课时或费用进行消耗确认 |
| 完课率 | 已完成课程内容占课程总内容的比例 |
| 预收费 | 培训服务实际完成前，由机构预先收取的培训费用 |
| 资金托管 | 将培训预收费存入专用账户，由符合条件的机构按规定监管 |
| 原路退回 | 退款返回至原支付渠道，降低盗用账户或洗钱风险 |
| 退费率 | 一段时间内退费订单数或退费金额占报名订单的比例 |
| 设备指纹 | 根据终端特征生成的设备识别标识，用于发现一机多账号 |
| 代学 | 非账号本人替学员完成学习任务或制造虚假学习进度 |
| 人工审核 | 风控系统不直接通过或拒绝，由审核人员结合证据作出决定 |

## 9. 国内合规约束与系统落实

| 合规主题 | 官方要求摘要 | 本项目落实方式 |
|---|---|---|
| 个人信息最小化 | 《个人信息保护法》将不满 14 周岁未成年人的信息列为敏感个人信息；处理敏感信息需要特定目的、充分必要性和严格保护措施，处理不满 14 周岁未成年人信息需取得监护人同意并制定专门规则 | 只保存必要字段；身份证使用哈希；记录监护人同意状态；限制敏感字段访问；提供删除、更正和申诉入口的设计说明 |
| 未成年人网络保护 | 《未成年人网络保护条例》要求必要信息范围、最小授权、访问审批和记录，并要求直播等服务合理限制未成年人消费；在线教育产品应按年龄特点提供服务 | 未成年人账号启用消费控制；高额打赏直接拦截或人工审核；敏感访问写审计日志；不基于未成年人数据做商业营销画像 |
| 培训预收费 | 教育部等六部门要求面向中小学生的校外培训预收费进入专用账户，并对收费周期、课时及退费权益进行监管 | 数据模型预留支付渠道、未消课金额和原支付标识；退费检查关注异常账户与原路退回；本教学版不实现真实资金托管 |
| 平台全流程监管 | 2025 年教育部平台管理办法覆盖选课、支付、退费、评价、投诉和资金异动风险预警，并支持未消课程费用原路退还 | 风控事件覆盖报名、退费和投诉扩展点；保留事件、评估、案件和操作日志，便于审计回溯 |

业务规则不得把未成年、残障、地域、家庭状况等身份本身当作欺诈结论；只能使用与具体业务风险直接相关、来源合法且可解释的行为信号。
