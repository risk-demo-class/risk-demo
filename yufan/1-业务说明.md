# 教育行业风控业务说明

> 场景：面向学生、家长和老师的在线教育平台  
> 范围：课程报名、学习、退费、直播互动  
> 基线契约：保持 `RiskCheckRequest(event_type, source_id, user_id, event_data)` 不变

## 一、业务目标

本项目把尚硅谷电商风控基线改造成教育风控系统，识别报名、退费、身份、设备关联和直播消费中的欺诈或滥用。系统继续复用原有“业务校验 → 信息补全 → 黑名单 → 风控决策”流程，只重写教育业务表、特征、事件校验、黑名单类型、数据和规则。

## 二、典型欺诈场景

| 场景 | 典型行为与识别信号 | 建议处置 |
|---|---|---|
| 批量新账号刷报名 | 同一设备控制多个注册不足 7 天的账号，集中报名同一课程 | 极高，拒绝 |
| 0 学时异常退费 | 学习不足 5 分钟即申请高额退费，或短期多次退费 | 高，人工审核 |
| 大额集中报名 | 1 小时购买多门高价课程，金额明显高于历史水平 | 高，人工审核 |
| 假学员/代理学习 | 同一设备关联不少于 5 个学员，或多个身份共用设备 | 极高，拒绝 |
| 身份与课程不符 | 用户角色、实名状态或学号与课程适用对象不匹配 | 中，标记核验 |
| 直播异常消费 | 新账号单场高额打赏，未成年人监护同意状态缺失 | 高，拦截后审核 |
| 黑名单再次访问 | 学号、证件哈希、设备指纹或直播账号命中黑名单 | 极高，直接拒绝 |

演示数据必须让“批量刷报名、0 学时退费、假学员代理”至少 3 类风险稳定命中，同时保留正常学员样本。

## 三、关键业务对象与字段

| 对象 | 关键字段 | 风控作用 |
|---|---|---|
| 用户 `UserInfo` | `user_id, role, student_id, id_card_hash, real_name_status, guardian_consent_status, register_at, device_id` | 账号年龄、实名、监护同意、同证/同设备多账号 |
| 课程 `Course` | `course_id, name, category, price, teacher_id, total_hours, target_role` | 课程价格、分类和适用身份判断 |
| 报名订单 `OrderInfo` | `order_id, user_id, course_id, total_amount, discount_amount, order_time` | 大额连报、优惠套利、夜间报名 |
| 学习进度 `LearningProgress` | `progress_id, user_id, course_id, total_minutes, completion_rate, last_active_at` | 0 学时退费、代学和进度突增 |
| 退费申请 `RefundRequest` | `refund_id, order_id, refund_amount, refund_reason, study_minutes_before_refund, apply_time` | 退费次数、金额、比例和退费前学习情况 |
| 直播打赏 `LiveReward` | `reward_id, user_id, live_session_id, reward_amount, device_id, reward_time` | 单次/单场金额、短时频率和设备关联 |

共 39 个字段，超过任务书“关键字段不少于 10 个”的要求。身份证只保存不可逆哈希，不保存明文。

## 四、业务事件类型

| `event_type` | `source_id` 对应实体 | 风控重点 |
|---|---|---|
| `课程报名` | `OrderInfo.order_id` | 新账号、大额连报、同设备多账号、身份不符 |
| `退费申请` | `RefundRequest.refund_id` | 学习时长、退费频率、累计金额和优惠套利 |
| `直播打赏` | `LiveReward.reward_id` | 未成年人消费、单场金额、短时频率和黑名单 |
| `学习行为` | `LearningProgress.progress_id` | 代学、设备关联、异常时段和进度突增 |

## 五、初版规则方向

| 编号 | 规则 | 条件摘要 | 决策 |
|---|---|---|---|
| EDU_R001 | 刷单式报名 | 同课程短期多个新账号且关联同一设备 | 拒绝 |
| EDU_R002 | 0 学时退费 | 学习时长小于 5 分钟并申请退款 | 人工审核 |
| EDU_R003 | 大额连报 | 1 小时累计报名金额大于 30000 元 | 人工审核 |
| EDU_R004 | 假学员代理 | 同一设备关联不少于 5 个学员 | 拒绝 |
| EDU_R005 | 退费连环 | 90 天退款不少于 3 次且累计大于 10000 元 | 标记 |
| EDU_R006 | 直播异常消费 | 新账号单场打赏大于 5000 元 | 人工审核 |
| EDU_R007 | 身份不符 | 角色或实名状态与课程适用对象不一致 | 标记 |
| EDU_R008 | 黑身份拦截 | 学号、证件哈希或设备命中黑名单 | 拒绝 |

阈值是教学初始值，后续根据造数分布调整，确保至少 3 条规则能命中样例数据。

## 六、行业术语

| 术语 | 含义 |
|---|---|
| 课程报名 | 选定课程并生成报名订单的过程 |
| 课消 | 完成学习后对已购课时或费用进行消耗确认 |
| 完课率 | 已完成内容占课程总内容的比例 |
| 预收费 | 培训服务完成前预先收取的费用 |
| 资金托管 | 预收费进入专用账户并按规定监管 |
| 原路退回 | 退款返回原支付渠道 |
| 设备指纹 | 根据终端特征生成的设备识别标识 |
| 代学 | 非账号本人替学员完成学习任务 |
| 人工审核 | 审核员结合证据对系统预警作出决定 |

## 七、合规要求

- 遵循个人信息最小化原则；不满 14 周岁未成年人的信息属于敏感个人信息，处理时应取得监护人同意并采取严格保护措施。
- 未成年人账号需要消费控制、访问最小授权、操作日志和申诉渠道；高额直播消费不能只依赖模型自动放行。
- 若平台开展面向中小学生的校外培训，预收费应按主管部门要求进入监管体系，退费优先校验原支付渠道和未消课金额。
- 风控只使用与具体业务风险直接相关的合法信号，不把年龄、地域或家庭状况本身当作欺诈结论。

官方依据：[个人信息保护法](https://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html)、[未成年人网络保护条例](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)、[校外培训预收费监管通知](https://www.moe.gov.cn/srcsite/A29/202110/t20211028_575840.html)、[全国校外教育培训监管与服务综合平台应用管理办法](https://www.moe.gov.cn/srcsite/A29/202503/t20250326_1184786.html)。
