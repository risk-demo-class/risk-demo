# Agent Design · 与 LLM 协作开发方法沉淀

> 本文记录在 **Bank-Risk** 项目中，使用 LLM（CodeBuddy / 类 Claude 编码助手）以"Vibe Coding"方式从 0 构建银行风控原型的**具体协作方法**：提示词策略、交互流程、代码审查方式与最佳实践。
> 适用于：希望用 LLM 快速产出"可运行、可讲解、可复盘"的代码原型的团队。

---

## 1. 协作总体原则

| 原则 | 含义 |
|------|------|
| **先决策后编码** | 让 LLM 先输出"方案对比 / 设计"，确认方向再写代码，避免返工 |
| **让 LLM 自己跑** | 要求"真实运行并输出指标"，而非只生成代码 |
| **文档即产出** | 讲解稿、README、协作复盘与代码同步生成 |
| **小步快跑** | 拆成"造数→特征→规则→训练→截图"等独立可验证步骤 |
| **显式踩坑** | 把每个 bug 修复沉淀为可复用规则 |

## 2. 提示词（Prompt）策略

### 2.1 五类提示词模板

**① 方案分析型**（动手前）
> "分析 X 的两种方式：A vs B。请从 [数据一致性 / 效率 / 资源 / 可复现 / 生产适配 / 调度监控] 维度对比，并给出不同场景推荐。"

→ 用于：数据来源（实时连库 vs 离线造数）、模型选型。

**② 任务委托型**（带约束）
> "正例:负例 = 1:4。接受计划并立即开始。要求：可运行、有指标、可复现。"

→ 关键：给出**量化约束**（配比、阈值）和**验收标准**（可运行）。

**③ 增量增强型**（避免过拟合）
> "把 5 份输出固化成 PNG 截图；引入噪声/难负样本避免过拟合，加一个'难负样本增强'开关。"

→ 关键：把"防过拟合"翻译成**具体机制**（边界化 + 对抗样本 + 高斯噪声 + 开关）。

**④ 审查修复型**
> "AUC 恒为 1.0，怀疑标签泄漏，请定位并修复。"

→ 关键：给出**怀疑方向**，让 LLM 自检而非盲改。

**⑤ 文档生成型**
> "准备 5–8 分钟讲解文档（含 5 环节）+ README + agent_design.md。"

→ 关键：明确**结构骨架**与**交付物清单**。

### 2.2 提示词要点
- **量化优先**：用数字代替形容词（"1:4"优于"均衡"，"val_auc=0.821"优于"还行"）。
- **指定文件**：让 LLM 读现有文件再改，避免臆造 API。
- **要求证据**："运行并贴出终端输出"比"请写好"可靠。
- **分步确认**：每步完成即验证，不一次性堆 10 个文件。

## 3. 交互流程（本项目实际走过的链路）

```
[1] 方案分析  → LLM 对比 实时连库 vs 离线造数，推荐离线（保留连库扩展点）
        ↓ 用户确认配比 1:4
[2] 环境探测  → LLM 探测 xgboost 缺失 → 装 3.4.0；读 config/feature/validator
        ↓
[3] 增量实现  → feature.py / validator.py(+2规则) / event.py / train_xgb_model.py
        ↓ 运行验证
[4] 防过拟合  → --hard-neg 开关 + 难负增强 + 概率化造数信号
        ↓
[5] 固化演示  → make_screenshots.py 生成 5 张 PNG + 5-运行说明.md
        ↓
[6] 文档交付  → 讲解文档 + README + 本文
```

每一步都要求 LLM **先读后写、写完即跑**，错误在当步闭环。

## 4. 代码审查（Review）方式

### 4.1 LLM 自检清单
- [ ] 函数返回值类型是否匹配调用处（曾踩：`generate` 返回 dict 非 tuple）
- [ ] 依赖版本 API 差异（XGBoost 3.x 移除 `use_label_encoder` / `early_stopping_rounds`）
- [ ] 标签泄漏（代理特征是否按 `is_fraud` 硬注入）
- [ ] 归一化是否破坏规则所需的原始量（需保留 `*_raw`）
- [ ] 中文输出是否乱码（matplotlib 需显式指定中文字体）
- [ ] 类型注解是否完整（`ctx()` 需显式构造 `TxnContext` 避免 lint ERROR）

### 4.2 人工复核重点
- 指标是否"过于完美"（AUC=1.0 先假设泄漏）
- 造数是否与正常样本保留**现实重叠区间**（否则模型线性可分，无泛化意义）
- 决策是否可解释、可审计（每条 reject 是否带 `trigger_rule` + `severity`）

## 5. 踩坑与最佳实践（Top 经验）

| # | 陷阱 | 现象 | 解决 / 最佳实践 |
|---|------|------|------------------|
| 1 | **标签泄漏** | AUC 恒 1.0 | 造数信号**概率化**（0.7），正常与欺诈样本保留重叠区间 |
| 2 | **归一化破坏规则** | `peer_cnt` 归一到 0.x，规则不触发 | 保留 `disperse_peer_cnt_raw` 供规则层用真实量 |
| 3 | **版本 API 差异** | XGBoost 3.x 报错 | 先探测环境再编码；移除已废弃参数 |
| 4 | **中文乱码** | 截图方框 | `plt.rcParams` 指定 `Microsoft YaHei` / `SimHei` |
| 5 | **类型推断 ERROR** | `ctx()` 返回类型不符 | 显式关键字构造 `TxnContext(...)` |
| 6 | **虚假完美指标** | 误判模型很强 | 用 `--hard-neg` 量化 train/val gap，暴露真实泛化 |
| 7 | **一次性堆代码** | 难定位 bug | 拆独立可验证步骤，每步运行 |

---

## 6. 效率提升点（量化感受）

- **从 0 到可跑闭环 < 半天**：造数、特征、规则、训练、截图、文档全部对话驱动。
- **样板代码零手写**：枚举、SQL 导出、matplotlib 图样由 LLM 生成。
- **文档与代码同源**：讲解稿 / README / 协作复盘一次成型，减少"写完再补文档"的债。

---

## 7. 适用边界与风险提示

- LLM 生成的指标/结论**必须真跑验证**，不要直接采信"看起来对"的代码。
- 金融风控涉及合规，规则阈值（见 `config.py`）需业务/合规双重确认，本原型仅供演示。
- 离线造数仅用于原型；生产须接真实数据并做特征监控（PSI / 漂移检测）。
