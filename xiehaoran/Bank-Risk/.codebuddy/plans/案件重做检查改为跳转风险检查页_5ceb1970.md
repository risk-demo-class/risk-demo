## 用户需求

将案件管理页「重做检查」按钮的行为从"调用后端自动重做接口"改为"跳转到风险检查页重新做检查"。

## 产品概述

在案件管理列表中，点击某条案件的「重做检查」按钮后，不再触发后端自动重做，而是跳转到「风险检查」页面，并携带该案件已知的事件类型、业务单号、客户号作为预填数据，让用户在该页面补充其余特征后手动重新发起决策。同时清理掉已不再需要的后端重做接口与前端封装，保持代码整洁。

## 核心功能

- 案件列表「重做检查」按钮改为跳转：点击后跳转至 `#/risk?event_type=...&source_id=...&user_id=...`
- 风险检查页预填：进入页面后自动读取 URL 中的 query 参数，回填事件类型（Tab）、业务单号、客户号三个字段，其余特征由用户手动补充
- 移除后端重做检查能力：删除 `recheck_case` 服务、`/cases/{case_id}/recheck` 路由、前端 `recheckCase` API 封装及相关 loading 状态
- 类型合法性保护：URL 中 event_type 若不属于已知事件类型，则仅预填 source_id/user_id，不切换非法 Tab

## 技术栈

- 前端：React + TypeScript + Ant Design（现有栈，无新增依赖）
- 路由：基于 `window.location.hash` 的前端 hash 路由（既有机制，不引入 react-router）
- 后端：FastAPI（仅做删除清理，无新增逻辑）

## 实现方案

### 总体策略

沿用项目现有 hash 路由机制（`App.tsx` 中 `go(key)` 设置 `window.location.hash`），将「重做检查」按钮改为设置带 query 参数的 hash 跳转；在 `RiskCheck` 组件挂载时解析 hash 内 query 部分并预填表单。后端及前端 API 中已无用的重做接口一并删除，避免死代码。

### 关键技术决策

1. **参数载体放在 hash 内而非 location.search**：因现有 `go()` 只写 `window.location.hash`，不会设置 `location.search`，所以参数必须放在 hash 之后（`#/risk?event_type=...&source_id=...&user_id=...`）。RiskCheck 用 `window.location.hash.split("?")[1]` 取 query 串，再用 `URLSearchParams` 解析。
2. **预填时机**：RiskCheck 在组件挂载（`useEffect`）时读取参数并 `form.setFieldsValue(...)`，同时若 event_type 合法则 `setEventType(...)`。由于 `App.tsx` 中 `key={page}` 按 page 区分，从 cases 切到 risk 会重新挂载 RiskCheck，挂载即触发预填，可靠无残留。
3. **事件类型合法性校验**：用 `EVENT_OPTIONS` 的 value 列表校验 URL 的 event_type；非法则跳过 event_type 预填，仅填 source_id/user_id，避免 Tabs 渲染异常。
4. **后端清理**：删除 `recheck_case`（service/case.py）与 `POST /{case_id}/recheck`（routers/case.py）以及前端 `recheckCase` 封装，彻底移除不再使用的自动重做能力，满足用户"一并移除"要求。

### 性能与可靠性

- 解析 query 为 O(1) 字符串操作，无性能开销；预填仅一次 `setFieldsValue`，不触发额外网络请求。
- 删除后端路由后，原 `process_event` 局部导入随之移除，进一步消除潜在循环导入风险。
- 向后兼容：跳转 URL 即使缺失某参数，RiskCheck 仍按默认 `initialValues` 渲染，不报错。

## 实现要点（防回归）

- 复用既有 `EVENT_OPTIONS` 做类型校验，不硬编码事件类型字符串。
- 跳转仅修改 `window.location.hash`，沿用 `App.tsx` 现有 hashchange 监听，不改动路由框架。
- `RiskCheck` 的 `initialValues` 保留默认样例，预填为挂载时叠加，不破坏"填充样例"按钮行为。
- 移除 `CaseBoard` 中 `recheckingId` 状态与 `recheck` 函数，操作列按钮去掉 `loading` 绑定，避免引用已删除的 `api.recheckCase`。

## 架构设计

### 数据流（改动后）

```
CaseBoard「重做检查」点击
  → window.location.hash = "#/risk?event_type=&source_id=&user_id="
  → hashchange → App setPage("risk") → 重新挂载 RiskCheck
  → RiskCheck 挂载 useEffect 解析 hash query → form.setFieldsValue 预填
  → 用户补充特征 → 点击「发起决策」→ api.riskCheck（既有接口）
```

- `App.tsx`：hash 路由调度，无改动（仅确认风险检查页可正常接收 query）。
- `CaseBoard.tsx`：操作列按钮改为跳转（移除 recheck 调用）。
- `RiskCheck.tsx`：新增 URL query 解析与预填逻辑。
- `api.ts`：删除 `recheckCase` 封装。
- 后端 `service/case.py`、`routers/case.py`：删除 recheck 相关代码。

## 关键代码结构（可选）

RiskCheck 新增解析逻辑示意（仅接口级）：

```typescript
useEffect(() => {
  const qs = window.location.hash.split("?")[1];
  if (!qs) return;
  const p = new URLSearchParams(qs);
  const eventType = p.get("event_type");
  const sourceId = p.get("source_id");
  const userId = p.get("user_id");
  const valid = EVENT_OPTIONS.some((o) => o.value === eventType);
  const vals: Record<string, string> = {};
  if (valid && eventType) { vals.event_type = eventType; setEventType(eventType); }
  if (sourceId) vals.source_id = sourceId;
  if (userId) vals.user_id = userId;
  if (Object.keys(vals).length) form.setFieldsValue(vals);
}, []);
```
