## 1. 业务背景说明（1 分钟）

**要说的一句话**：银行面临电诈、洗钱、伪冒盗刷、多头借贷四类资金风险，传统"硬编码阈值"规则误杀率高、迭代慢；本项目用"XGBoost 模型 + 可解释业务规则"双引擎，做实时交易风险评分与分级决策。

**要点（口播稿）**：
- **业务问题**：转账/卡交易/贷款申请/还款/登录 五类事件里，存在快进快出、分散转入集中转出、异地盗刷、夜间盗卡、多头借贷等欺诈模式。人工审核成本高、响应慢。
- **应用场景**：交易实时拦截（毫秒级返回 `pass/review/reject/freeze/report` 五级决策）、贷前审查、反诈报送。
- **预期价值**：
  - 模型捕获非线性、弱信号组合（如"中等金额 + 异地 + 凌晨"才可疑）；
  - 规则层提供**可解释、可审计**的决策依据，满足监管对"为何拒绝"的要求；
  - 离线造数 → 可复现训练，正例:负例 = 1:4（银行真实欺诈率约 0.2），避免样本失衡。

**过渡句**："下面我直接把代码跑一遍，让大家看到从数据到决策的全链路。"

## 3. XGBoost 模型评估（1 分钟）

**关键指标（取自 `scripts/eval_history.jsonl`）**：

| 模式 | train_auc | val_auc | val_f1 | 说明 |
|------|-----------|---------|--------|------|
| 基线 BASE | 1.000 | 1.000 | 1.000 | 代理特征硬注入，标签泄漏，**虚假完美** |
| HARD（难负增强） | 1.000 | **0.821** | **0.889** | 概率化派生 + 难负边界化，暴露真实泛化 |

**口播重点**：
- **为什么 AUC 不是 1.0 反而更可信**：初版把"是否欺诈"直接写成强特征，模型不学也会满分（标签泄漏）。修复后概率化造数信号 + 注入"难负样本/对抗性难正样本"，val_auc 落到 **0.821** —— 这才是模型真实泛化能力。
- **特征重要性（截图 05）**：`geo_deviation`、`disperse_peer_cnt`、`over_query_freq`、`login_brute_freq` 等位居前列，与业务直觉一致（异地、分散对手、征信查询密集、爆破登录）。
- **过拟合防控**：`--hard-neg` 开关开启后，val_auc 与 train_auc 的 gap 即衡量过拟合程度，本原型已实现"可量化、可对比"的增强机制。

**过渡句**："模型给了概率，但业务要的是'能不能解释、能不能拦'。这就引出规则层。"

## 4. 业务规则讲解（2 分钟）

**设计哲学**：模型输出 `risk_score ∈ [0,1]`，规则层把分数"翻译"成**可审计的决策**。规则分两类：

**A. 模型驱动规则（提炼自 XGBoost）**
从特征重要性反推核心规则，例如：
- `geo_deviation`（异地突变）+ 中等金额 → 伪冒盗刷高风险
- `disperse_peer_cnt` 高（分散转入）→ 洗钱/资金归集信号
- `over_query_freq` 高（短期多查征信）→ 多头借贷

**B. 硬规则 / 一票否决（合规兜底，`config.py`）**
- 命中黑名单（`account/device/ip/phone/id_card/merchant/beneficiary`）→ **freeze 保护性止付**（severity=4 一票否决）
- 单笔 ≥20 万 → AML 大额报送（report）
- 转账对手数 ≥10/1h → 进入模型复核

**决策流（对照 `feature.py` + `validator.py`）**：
```
进件 → TxnContext 组装 → DISPATCH_TABLE 路由 8 规则 → 触发规则聚合 severity
     → 模型打分 risk_score
     → 融合决策: max(severity) 达阈值 或 score 超阈 → reject/freeze/report
     → 否则 pass / review
```

**实际应用方式**：
- 规则可"热插拔"（`DISPATCH_TABLE` 增删一行即上线一条新策略），无需重训模型；
- 模型与规则**并行**，规则优先（合规要求），模型补盲（捕捉弱信号组合）；
- 每条拒绝都带 `trigger_rule` + `severity`，满足监管可解释性。

**过渡句**："整个系统是我用 LLM 协作'边聊边写'出来的，最后聊聊这个体验。"

## 5. Vibe Coding 协作复盘（1 分钟）

**效率提升点**：
- **从 0 到可跑闭环 < 半天**：数据造数、特征工程、规则引擎、训练脚本、截图文档全部由对话驱动生成，省去样板代码时间。
- **结构化分工清晰**：让 LLM 先"分析数据来源方案（实时连库 vs 离线造数）"再动手，避免方向错误。
- **文档即产出**：讲解稿、README、协作复盘一次性生成，与代码同步。

**经验教训（踩坑）**：
1. **标签泄漏是最大陷阱**：第一版 AUC=1.0 是假的。务必让"造数信号"概率化、并与正常样本保留重叠区间，才能测出真实泛化。
2. **归一化别动规则要用的原始量**：特征归一化后，`peer_cnt` 变 0.x，规则拿不到真实对手数 —— 需保留 `disperse_peer_cnt_raw`。
3. **版本差异要显式处理**：XGBoost 3.x 已移除 `use_label_encoder` / `early_stopping_rounds`，依赖 LLM 前先探测环境。
4. **中文截图要配字体**：matplotlib 默认无中文字体，需显式指定 `Microsoft YaHei`，否则截图乱码。
5. **让 LLM 自己跑、自己验证**：要求"真实运行并输出指标"比"只生成代码"可靠得多。

**收尾句**："代码可跑、模型可解释、协作可复盘 —— 这就是 Bank-Risk 原型的价值。"
