# 旅游出行风控系统项目大纲（工业级算法项目）

> 基线项目：尚硅谷 `AI_Risk` 风控系统（电商版）
> 本项目：旅游出行风控系统（机票 / 酒店 / 签证 / 团票 / 跨境订单）
> 定位：简历算法项目，代码体现特征工程、树模型风控、规则 + 模型双链路

## 1. 项目定位与简历亮点

本项目不是把电商风控换皮，而是按旅游行业重做业务模型：

- 规则引擎负责快速拦截明显异常，低延迟、可解释、可运营。
- XGBoost 离线训练后提供 0-100 分精细化风险评分，按阈值拦截。
- 用户行为时序特征：7 天下单次数、连续退改次数、同设备切换多账号订酒店。
- DeepSeek 本地接口辅助识别订单备注中的黄牛暗号、违规拼团信息。
- 特征全部配置化，方便增减特征、迭代模型。
- 提供模拟正负样本 CSV，支持本地训练和面试讲解模型效果。
- 提供模型评估代码：准确率、召回率、混淆矩阵。
- 提供 Dockerfile / docker-compose 一键部署和 Postman 接口示例。

## 2. 业务分析

### 2.1 业务边界

用户在 OTA 平台完成：

- 机票预订、退改签
- 酒店预订、预授权扣款
- 签证申请
- 团票 / 拼团报名
- 跟团游和跨境订单

### 2.2 电商交易风险 vs 旅游行业特有风险

| 维度 | 电商交易风险 | 旅游行业特有风险 |
|---|---|---|
| 交易对象 | 实物商品 | 机票、酒店、签证、行程服务 |
| 典型风险 | 刷单、退款套利、多地址、物流投诉 | 机票退改套利、酒店预授权、团票批量、跨境订单 |
| 时序特征 | 收货地址、复购行为 | 连续退改、临期出行、多国签证、设备多账号 |
| 身份关联 | 收货人 / 手机号 | 乘客、护照号、签证号、出行人 |
| 核心标签 | 商品与物流 | 航班、酒店、目的地、出行日期 |

### 2.3 旅游特有风险清单

| 风险场景 | 说明 | 典型信号 |
|---|---|---|
| 机票退改套利 | 低票价改签高价票、退改险套利 | 连续退改、退改金额异常、临期退票 |
| 酒店预授权风险 | 预授权与实际支付不一致、盗刷预授权 | 预付金额与订单金额不符、取消后仍扣款 |
| 团票批量下单 | 同账号 / 设备短时间批量预订 | 1 小时多单、同航班多乘客、备注暗号 |
| 跨境订单风险 | 新用户大额跨境、支付国家不一致 | 注册 < 7 天、大额、目的地高风险 |
| 签证黑产 | 拒签历史、多国短期申请、材料复用 | 90 天拒签多次、30 天多国申请 |
| 黄牛暗号 / 违规拼团 | 订单备注中的行业暗号 | LLM 识别备注语义 |

### 2.4 事件类型

| event_type | source_id | 业务含义 |
|---|---|---|
| 下单 | 订单 ID | 机票 / 酒店 / 团票预订 |
| 支付 | 订单 ID | 支付、预授权 |
| 退改申请 | 订单 ID 或退改单 ID | 机票改签、酒店取消 |
| 签证申请 | 签证申请 ID | 签证提交 |
| 拼团报名 | 拼团单 ID | 团票 / 拼团 |

### 2.5 风控决策输出

- 决策：`通过 / 标记 / 人工审核 / 拒绝`
- 风险分：0-100 分，规则分与模型分双轨融合
- 输出审计：`risk_event / risk_feature / risk_assessment / risk_case`

## 3. 双链路风控架构

```text
旅游业务事件
    |
    v
process_event 统一入口
    |--- 1. 业务实体校验
    |--- 2. 事件补全
    |--- 3. 黑名单前置拦截（护照号 / 设备 / 支付账号）
    |
    v
链路 A：规则引擎（低延迟快速拦截）
    |--- 加载 JSON 规则
    |--- 极高风险一票否决 -> 直接拒绝
    |--- 命中规则生成 rule_score
    |
    v
链路 B：XGBoost 模型（精细化评分）
    |--- 特征配置读取
    |--- 用户 / 订单 / 设备 / 乘客 / 时序特征计算
    |--- XGBoost predict -> sigmoid 校准 -> ml_score 0-100
    |
    v
LLM 辅助分支（仅订单备注存在时启用）
    |--- DeepSeek 本地接口识别黄牛暗号 / 违规拼团
    |--- 输出 remark_llm_score 与语义标签
    |
    v
final_score = a * rule_score + b * ml_score + llm_bonus
    |--- 映射 通过 / 标记 / 人工审核 / 拒绝
    |--- 落库 risk_event / risk_feature / risk_assessment / risk_case
```

性能策略：

- 规则命中 `极高` 时直接拒绝，不等待 ML / LLM。
- 无订单备注时不调用 LLM，避免阻塞主链路。
- LLM 超时、不可用时按 0 分兜底，不影响业务可用性。

## 5. 特征工程

### 5.1 特征配置文件

新增 `config/features.yaml`，所有特征通过配置注册：

```yaml
features:
  - name: user_orders_7d
    group: user
    entity: user_id
    category: time_series
    enabled: true
    description: 7天下单次数
    sql: |
      SELECT COUNT(*) FROM order_info
      WHERE user_id = :user_id
      AND create_time >= DATE_SUB(NOW(), INTERVAL 7 DAY)

  - name: order_is_night
    group: order
    entity: order_id
    category: order
    enabled: true
    description: 是否凌晨下单
```

`app/engine/feature_registry.py` 读取配置，动态生成特征计算字典；`FEATURE_COLUMNS` 由配置导出，保证训练 / 推理 / 测试完全一致。

### 5.2 特征族

用户特征（14 个）：

`user_total_orders`、`user_orders_30d`、`user_orders_7d`、`user_total_amount`、`user_avg_order_amount`、`user_max_order_amount`、`user_cancel_count`、`user_refund_count`、`user_refund_rate`、`user_refund_amount`、`user_visa_reject_90d`、`user_visa_countries_30d`、`user_passenger_id_count`、`user_device_count`

订单特征（8 个）：

`order_total_amount`、`order_passenger_count`、`order_hotel_room_count`、`order_flight_count`、`order_trip_days`、`order_days_to_departure`、`order_is_night`、`order_dest_risk_score`

行为时序特征（重点）：

`user_orders_7d`、`user_consecutive_refund_change`、`device_user_count_7d`、`device_hotel_account_count`、`same_pay_account_1h_orders`、`same_flight_1h_bookings`

LLM 语义特征：

`remark_llm_score`、`remark_scalper_flag`、`remark_illegal_group_buy_flag`

### 5.3 特征命名规范

`user_*` -> 用户维度

`order_*` -> 订单维度

`device_*` -> 设备维度

`passenger_*` / `addr_*` -> 乘客 / 联系人维度

`remark_*` -> LLM 语义维度

## 6. 规则模块

### 6.1 规则引擎

- 复用 JSON 条件表达式：`> >= < <= == != in not_in between and or`
- 规则存 `risk_rule`，支持按 `event_type` 加载
- 极高风险一票否决，不等待模型
- 规则分与模型分融合

### 6.2 旅游业务规则

| 规则 | 条件 | 等级 | 动作 |
|---|---|---|---|
| R001 拒签历史拦截 | 90 天拒签 >= 2 次 | 极高 | 拒绝 |
| R002 短期多国签证 | 30 天申请 >= 3 个国家 | 高 | 人工审核 |
| R003 连续退改套利 | 连续退改 >= 3 次 | 高 | 人工审核 |
| R004 同设备多账号订酒店 | 同设备 7 天关联 >= 3 个账号订酒店 | 高 | 人工审核 |
| R005 大额跨境游 | 单笔订单 > 50000 元 | 高 | 人工审核 |
| R006 团票批量下单 | 同支付账号 1 小时 >= 5 单 | 极高 | 拒绝 |
| R007 酒店预授权不一致 | 预授权金额与订单金额偏差异常 | 高 | 人工审核 |
| R008 黄牛囤票 | 同航班 1 小时预订 >= 5 张 | 极高 | 拒绝 |
| R012 0 点突击下单 | 凌晨 1-5 点 + 行程 < 7 天 | 中 | 标记 |
| R018 乘客信息不一致 | 乘客证件与历史匹配 < 30% | 中 | 标记 |
| R025 新用户大单 | 注册 < 7 天 + 订单 > 10000 元 | 中 | 标记 |
| R030 黑护照拦截 | 护照 / 证件命中黑名单 | 极高 | 拒绝 |
| R040 备注命中黄牛暗号 | LLM 判定 remark_risk_score >= 80 | 高 | 人工审核 |
| R041 违规拼团 | LLM 判定违规拼团 | 高 | 人工审核 |

## 7. 数据与模型训练

### 7.1 模拟正负样本 CSV

新增 `scripts/gen_train_csv.py`，生成 `data/travel_risk_train.csv`：

- 正样本（1）：黄牛囤票、退改套利、跨境大额、签证黑产、设备多账号、LLM 暗号
- 负样本（0）：正常下单、正常酒店预订、正常签证申请
- 推荐规模：>= 2000 条，正样本占比 25%-35%，固定随机种子可复现
- CSV 字段：`user_id, order_id, event_type, label` + 特征列

### 7.2 训练脚本

`scripts/train_xgb_model.py`：

- 从 CSV 或 DB 加载数据
- 80/20 stratified split
- XGBoost + `scale_pos_weight`
- early stopping
- 输出 `app/engine/xgb_model.json`
- 输出特征重要性 TOP 10

### 7.3 模型评估

新增 `scripts/evaluate_model.py`：

- 准确率 accuracy
- 精确率 precision
- 召回率 recall
- F1
- AUC
- 混淆矩阵
- classification report
- 输出阈值扫描建议（面试可讲：选阈值不是只看准确率）

### 7.4 回填

`scripts/backfill_ml_score.py`：用训练好的模型回填 `risk_assessment.ml_score / ml_decision`。

## 8. LLM 辅助判别

### 8.1 DeepSeek 本地接口

`.env` 配置：

```ini
LLM_ENABLED=true
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL_NAME=deepseek-r1:7b
LLM_API_KEY=ollama
LLM_TIMEOUT_SEC=10
```

新增 `app/llm/remark_analyzer.py`：

- 使用 OpenAI 兼容接口调用本地 DeepSeek
- Prompt 要求输出 JSON：

```json
{
  "risk_level": "high",
  "risk_type": "scalper_code",
  "score": 85,
  "reason": "备注疑似黄牛暗号"
}
```

- 解析失败 / 超时 / 服务不可用时，默认 `score=0`，不阻断业务
- 结果写入 `remark_llm_score` 等特征
