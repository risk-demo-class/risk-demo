# 旅游出行风控系统 - 任务说明

## 1. 任务背景

基于尚硅谷 `AI_Risk` 电商风控系统的成熟架构，完成一个旅游出行风控系统，覆盖机票、酒店、签证、团票、跨境订单等 OTA 业务场景。

任务重点：

- 复用风控核心 9 张表、7 步决策流水线、规则引擎、XGBoost 双轨融合。
- 替换业务层为旅游行业模型。
- 体现规则 + 模型双链路、特征工程、模型评估、LLM 辅助判别。
- 产出可运行、可讲解、可部署的简历项目。

## 2. 业务说明交付要求

按任务书要求，项目需提供业务说明文档，并满足：

### 2.1 典型欺诈场景 >= 3 种

至少包含：

1. 黄牛囤票
2. 机票退改套利
3. 酒店预授权异常
4. 团票批量下单
5. 跨境大额订单
6. 签证黑产
7. 同设备多账号订酒店
8. 订单备注黄牛暗号 / 违规拼团

### 2.2 关键业务字段 >= 10 个

至少包含：

`order_id`、`user_id`、`order_type`、`total_amount`、`dest_country`、
`depart_date`、`return_date`、`passenger_count`、`pay_account`、
`device_id`、`ip_address`、`order_remark`、`flight_no`、`passport_no`。

### 2.3 业务事件类型 >= 3 种

- 下单
- 支付
- 退改申请
- 签证申请
- 拼团报名

### 2.4 行业术语表 >= 5 个

至少包含：

- OTA
- PNR
- 退改
- 预授权
- 团票
- 黄牛暗号

## 3. 工业级交付要求

1. 区分电商交易风险与旅游行业特有风险。
2. 双风控链路：
   - 规则引擎：快速拦截明显异常，低延迟。
   - XGBoost：离线训练 0-100 分风险评分，阈值拦截。
3. 用户行为时序特征：7 天下单次数、连续退改次数、同设备多账号订酒店。
4. DeepSeek 本地接口：识别订单备注黄牛暗号、违规拼团。
5. 特征配置化：`config/features.yaml` 可增减特征。
6. 模拟正负样本 CSV：支持本地训练。
7. 模型评估：准确率、召回率、混淆矩阵。
8. Docker / Postman / README 部署交付。

## 4. 验收清单

- [ ] 旅游业务表 >= 11 张，风控核心表复用。
- [ ] 事件类型、黑名单类型、规则分类按旅游行业定义。
- [ ] 规则引擎可快速拦截，极高风险一票否决。
- [ ] XGBoost 训练产出 `val_auc >= 0.7`、`val_f1 >= 0.5`。
- [ ] 至少 1 个高风险用户可被系统识别。
- [ ] 提供正负样本 CSV 和评估脚本。
- [ ] DeepSeek 本地接口可调用且失败有兜底。
- [ ] `pytest tests/` 全绿。
- [ ] Docker 一键启动。
- [ ] Postman 接口示例齐全。
