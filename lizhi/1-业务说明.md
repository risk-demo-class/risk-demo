# 1-业务说明：旅游行业风控（OTA：机票 / 酒店 / 签证 / 跟团游）

> 业务边界：用户经 OTA 平台完成机票、酒店、签证、跟团游的"注册 → 搜索 → 下单 → 支付 → 出票/确认 → 出行核销 → 退改售后"全流程。风险事件统一按基线契约 `RiskCheckRequest(event_type, source_id, user_id, event_data)` 接入风控引擎。

## 一、典型欺诈场景（6 类）

| 场景 | 典型行为 | 风控信号 |
|---|---|---|
| 1. 机票黄牛囤票 / 占座倒卖 | 放票瞬间批量抢购热门航班、同一支付账号短时预订多张同航班、占座不付款后高价转售 | 同账号/设备/支付账户高频下单、短时同航班多人、出票率异常低 |
| 2. 退改签诈骗 / 病退材料造假 | 冒充航司客服以"航班取消"诱导转账；黑产伪造就医材料代办全额退票 | 退改时段集中、材料异常、收款账户与购票人分离、命中电诈黑名单 |
| 3. 酒店"到店无房"与恶意索赔 | 幽灵/虚假房源上架；团伙利用到店无房、免费取消规则批量索赔 | 房源信息异常、同设备/同 IP 关联多人索赔、索赔频次与金额异常 |
| 4. 签证材料造假 / 拒签隐瞒 | 伪造在职证明、银行流水，隐瞒拒签历史，短期多国密集申请 | 90 天内多次拒签、30 天内申请多国签证、材料核验失败 |
| 5. 营销薅羊毛 / 虚假交易 | 批量套取新客优惠、红包、立减金；刷单炒信、刷好评 | 设备农场、手机号池、同设备关联多账号、注册即下单 |
| 6. 账户盗用 / 积分里程套现 | 盗号后兑换积分、绑卡盗刷、异地或新设备下单消费 | 登录地与常用地不符、新设备大额订单、乘客证件与历史不一致 |

## 二、关键业务字段（43 个，覆盖任务书 A.1 全部 7 张必建业务表）

| 业务表 | 核心字段 | 业务含义 |
|---|---|---|
| `UserInfo` | user_id, name, real_name_status, vip_level, account_age_days | 用户标识、姓名、实名状态（旅游强制）、会员等级、注册时长 |
| `OrderInfo` | order_id, user_id, order_type, total_amount, dest_country, depart_date, return_date, passenger_count | 订单号、下单用户、业务类型（机票/酒店/签证/跟团游）、订单金额、目的地国家、出发/返回日期、乘客数 |
| `PassengerInfo` | passenger_id, name, id_type, id_number, nationality, age | 乘客标识、姓名、证件类型（身份证/护照）、证件号、国籍、年龄；1 个订单对应 N 个乘客 |
| `VisaApplication` | visa_id, user_id, dest_country, visa_type, reject_history, submit_time | 签证申请号、申请用户、目的地国家、签证类型、拒签历史、提交时间 |
| `BookingHotel` | booking_id, order_id, hotel_id, check_in, check_out, room_count, is_refundable | 酒店预订号、所属订单、酒店标识、入住/离店日期、房间数、是否可免费取消 |
| `BookingFlight` | booking_id, order_id, flight_no, depart_airport, arrive_airport, cabin_class | 机票预订号、所属订单、航班号、出发/到达机场、舱位等级 |
| `BlacklistExtra` | entry_id, type, value, reason, expire_at | 黑名单记录标识、类型（设备指纹/IP/护照号/签证号/身份证号）、命中值、加入原因、有效期 |

> 说明：上述字段与任务书 A.1 的 schema 一一对应，任务 2 的 `models_business.py` / DDL 及任务 3 的三大特征族（用户 / 订单 / 地址）均直接基于这 7 张表取数。

## 三、业务事件类型（8 种）

| event_type | 含义 | 说明 |
|---|---|---|
| ORDER_CREATE | 下单/预订 | 机票、酒店、签证、跟团游统一入口，拦截黄牛与大额异常 |
| PAYMENT_SUCCESS | 支付成功 | 校验支付账号、设备与订单一致性，防盗刷 |
| TICKET_ISSUE | 出票/确认 | 机票出票、酒店确认，资源占用关键点 |
| REFUND_APPLY | 退改签申请 | 退票/改期/取消，防病退造假与恶意退款 |
| CHECK_IN | 出行/入住核销 | 防到店无房、未出行却核销 |
| VISA_APPLY | 签证申请 | 拒签历史、多国密集申请核验 |
| CLAIM_SUBMIT | 索赔/投诉 | 到店无房、航变索赔，防团伙恶意索赔 |
| REVIEW_SUBMIT | 评价发布 | 防刷单炒信、虚假点评 |

## 四、行业术语表（10 个）

| 术语 | 释义 |
|---|---|
| OTA | Online Travel Agency，在线旅游平台（携程、同程、飞猪等） |
| PNR | 旅客订座记录，机票预订的唯一编码 |
| 间夜 | 房间数 × 入住晚数，酒店核心经营指标（间夜量） |
| 航变 | 航班变更（取消/时刻调整），退改签与理赔的触发点 |
| 出票 | 支付后航司/代理生成有效客票，出票后改退成本升高 |
| 切位/占位 | 代理向航司批量预订舱位再转售，是黄牛囤票的风险点 |
| 拒签 | 签证申请被使领馆拒绝，与签证代办欺诈直接相关 |
| 到店无房 | 客人预订后到店无房可住，属平台高赔付风险事件 |
| 不合理低价游 | 明显低于成本的跟团游，靠购物/自费回本，监管明令整治 |
| 包价旅游合同 | 旅行社与旅游者的打包服务书面合同，《旅游法》第 58 条要求 |

## 五、国内监管合规要点

- 《旅游法》第 52、58 条：旅游者个人信息保密；包价旅游合同采用书面形式并载明双方基本信息。
- 《在线旅游经营服务管理暂行规定》（文旅部令第 4 号，2020-10-01 施行）：平台对平台内经营者实名核验、行政许可与资质登记（第 11 条）；保障旅游者个人信息与数据安全（第 14 条）。
- 实名制：机票记名（购票证件与乘机证件一致）；酒店住宿实名登记（《旅馆业治安管理办法》第 6 条）；跟团游游客信息实名登记。
- 《个人信息保护法》《数据安全法》《网络安全法》：身份证/护照等敏感个人信息最小必要收集、加密/脱敏存储、出境合规。
- 《反电信网络诈骗法》：机票退改签电诈场景的识别、预警与止付配合。
- 落地要求：证件号等敏感字段哈希存储；黑名单类型扩展为设备指纹 / IP / 护照号 / 签证号 / 身份证号（对应 `BlacklistExtra`）。

> 调研来源：同程旅行全链路风控实践、在线旅游经营服务管理暂行规定、旅游法、旅馆业治安管理办法、民航记名客票规则、机票退改签诈骗公开案例。
